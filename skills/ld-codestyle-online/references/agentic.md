# README 模块索引与旧 Agentic.md 收敛

**模块地图统一由所属 `README.md` 承担，不再新建或续写 `Agentic.md` 平行索引。**保留 `Agentic/` 实现与记忆目录；宿主 `AGENTS.md` 仍有独立职责，不在替代范围。本文沿用 `references/agentic.md` 路径以兼容技能内的引用，但不再提供旧文件的生成模板；新区域使用 [README 模板](../templates/module-readme.md)。

README 是可核地图，不是更高权限。当前人类指令、工程规则、真实代码/接口/序列化契约优先；索引过时不能反过来修改代码迎合它。它维持业务说明、边界和操作入口，同时声明记忆入口，不能退化成只有链接的空壳。详细层级与按需读取见 [共享上下文规范](directory-context.md#关联范围决定层级)。

## 放在哪里与何时维护

在已采用规范的一方 Core 根和有独立责任的模块区域使用现有 README；目录不必叫 Core 或 Base。README 可以与所说明的模块目录同级，明确列出所管区域、记忆真实路径和排除项，不能把物理父目录直接当逻辑范围。

从公共入口到目标区域读取适用约定和条目，再沿实际依赖补读。跨上层/兄弟模块的联动知识上提到各方共同读取层，纯局部知识下放；父索引作地图，子区域保留细节，正文按关联范围归属而非一律堆根。普通结构叶子如 Scripts、Agentic、Editor、Resources、Prefabs、Scenes、Textures、Sample 不重复铺空索引，除非本身是独立模块；不自动接管第三方、生成或缓存目录。

授权写任务只维护实际触及、存在真实增量的区域。只读不改，安装/升级技能不等于全仓迁移授权。新增文档由 Unity 正式导入产生 `.meta`，保留已有 GUID；模块本身迁移还须另核 namespace、asmdef 和序列化兼容，不能用文档收敛掩盖代码/资产搬迁。

## 收敛步骤与完成条件

1. **核原入口与所有权**：检查旧 Agentic.md、现有 README/Readme、入链、正文与 Git 脏状态。在本次授权责任区内处理；保护人工内容，不能覆盖同名文件，也不制造只差大小写的路径。
2. **保全后归位**：旧模块地图、业务边界和入口进入所属 README；深度架构与具体记忆进入其正确责任层，由 README 指路。保留有效正文、来源、日期、条目标识、条件和已有 Unity `.meta` 身份；合并文件时先核引用，不让两个 GUID 随意互换，不把无损搬迁当作压缩授权。
3. **更新实际读取入口**：修正所有受影响的相对链接、父子地图和明确引用旧文件的配置/宿主入口；受保护文件不能改时保留阻断，不绕审批。由旧路径进入、由上层进入、只处理某一关联方时，都应找到同一有效说明。
4. **停用旧正文**：验证接收内容和链接后退役旧 Agentic.md。确需兼容的旧入口只能写新路径、原 scope 和迁移说明，注明剩余引用及退役条件，保持**单一有效正文**；不能让 README 与 Agentic.md 各写一套。无兼容需要时按授权保全后移除旧入口；历史仍可从 Git/备份追溯。
5. **按范围验收**：逐项核有效知识已接收、单条 scope 正确、入链和相对链接可达、无双写、人工内容与 meta 未受损。仅新增 README 不算完成；有冲突或受保护入口未改，明确“迁移未完成”、受影响范围和下一责任。PR 中修规范/模板不等于任何业务项目已完成迁移。

每份实际 README 都须独立说明持久共享属性、逻辑作用域、维护边界、创建日期与最近修改日期，使用 [统一模板](../templates/module-readme.md) 并按真实增量填写变更记录，不复制第二套索引模板。保留许可来源与有效历史，不保存凭据、宿主私有记忆、全量排错日志或臆测进度。

公开目标：只保留非敏感变更记录，不附模型/Bot/客户端/计算机/人类显示名，也不在其他正文补记。未知不默认私有；公开前检查并脱敏文件和待推送历史中的证件号、密钥等隐私，保留合法版权/许可来源。仅经核私有目标按Commit规则记录真实操作身份。
