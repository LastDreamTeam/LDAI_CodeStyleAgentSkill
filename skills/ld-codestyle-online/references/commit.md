# 提交、混合贡献与真实交付

## 先核目标可见性

commit 前确认实际推送目标，push 前再核托管平台当前可见性，包括 push URL、fork 与 PR base；不能仅凭仓库名、HTTPS地址、能否匿名克隆或 `private=false` 推断公开（企业 `internal` 不等于 `public`）。多个目标只要有一个公开，就按公开格式准备。未知/查询失败不默认私有，不生成带身份的首行，不向未核目标推送；企业内部可见性先核其披露规则，未明确时同样暂停。

### 公开仓库：省略整个模型身份段

目标经核为 **public（非私有公开仓库）** 时，不记录 `#模型` / `##模型：` 或混合 `##主人 + 模型：` 身份段，直接以具体改动摘要作首行。Bot、客户端、模型、计算机名及混合首行的人类显示名均不附带；不留空段、不写“已脱敏”身份占位，不转移到正文、trailer、PR或共享记忆。问题与解决两节仍保留，使用空行分隔：

```text
补充公开提交隐私规则

##问题：公开提交不应附带内部执行身份或敏感资料。

##解决：省略身份段，检查并脱敏本次公开内容；填写真实验证和未验边界。
```

该例外优先于下文所有身份、计算机名和混合首行规则，也适用于公开 PR 的 merge/squash 消息及继承 Commit 身份要求的 README/MEMORY/USER/DEBUG 变更记录。公开记录保留日期、动作、条目标识、原因、验证及非敏感来源，不换位置补记操作模型。混合贡献仍可用“人类既有约定 / 本次实现”等不暴露身份的文字说明，不冒认贡献。必要的合法版权/许可署名不是模型执行记录，不借此抹除原作者；不自动改写历史、Git author/email或受保护人工注释。

### 私有仓库：首行按实际贡献选择

纯 Agent 改动沿用：

```text
##模型：<产品短名或Bot名> + <实际模型标识> PC:<实际计算机名> | <本次具体改动短摘要>

##问题：实际症状、需求缺口或根因及影响范围。

##解决：改了什么、为何这样改；验证结果及未验证的边界。
```

本次暂存变更涉及人类标记的注释或其明确关联的代码/设计约定时，不把整体成果完全记成 AI 自己的，使用混合贡献格式：

```text
##主人 + 模型：<产品短名或Bot名> + <实际模型标识> PC:<实际计算机名> | <本次具体改动短摘要>

##问题：实际症状、需求缺口或根因及影响范围。

##解决：说明人类贡献/既有约定与 Agent 本次改动各自的范围；真实验证和未验部分。
```

其中 `主人` 来自本安装的 **`human_commit_name`**，默认值是“主人”；代码人类标识由独立的 **`human_name`** 控制，默认 `LD`。修改显示名为“褪色的梦”后，同一混合首行变为 `##褪色的梦 + 模型：…`，**不加 `【】`**，也不把源码里的 `LD:` 替换成网名。设置说明和命令只放在[README 参数设置](https://github.com/LastDreamTeam/LDAI_CodeStyleAgentSkill#参数设置)。

## 客户端、Bot 与计算机身份

以下身份规则仅适用于已核私有目标，同时适用于纯 Agent 和混合贡献首行。计算机字段简写为 `PC:<实际计算机名>`，前留一个空格，放在模型身份之后、摘要分隔符之前，不再使用中文括号。公开目标不采集或输出这些字段。

- **产品短名，不附厂商**：`OpenAI Codex` / `OpenAICodex` 写为 `Codex`；其他产品使用其可辨识的产品名，不拼接厂商。已核实的独特 Bot 写自己的名字，不把 GitHub 登录账号当执行者。生成器只对上述两种明确旧称作兼容映射，未知名字不盲目截断；调用者仍须填写真实产品短名。
- **真实模型必填**：先从当前会话、宿主有效配置或执行回执核实本次实际型号；产品名、厂商名、Bot名、`auto`、`unknown`、`latest` 或示例占位都不能替代型号。缺少可核型号时先查证，不凭 Codex 产品名猜模型，也不以厂商兜底生成貌似完整的私有首行。缩短的是产品名和计算机标签，**准确模型ID原样保留**，不能顺带删除其命名空间、版本或后缀。
- 生成器拒绝缺失型号、部分明显非型号标签和占位，但无法证明任意输入是真实模型；字符串通过不等于身份已核实。公开模式不需要型号，继续在读取身份之前直接返回已脱敏摘要。

| 执行身份 | 首行身份部分 |
|---|---|
| Codex、ClaudeCode、Cursor、VSCode/Visual Studio Copilot、Other Agent Plugin、DeepSeekHarness 等桌面/本地 Agent | 产品短名 + 实际模型标识 PC:实际计算机名 |
| 已核实具有独特、非默认名称的 Hermes Bot、Grok Bot、GPT Dot 等实例 | 实际独特 Bot 名 + 实际模型标识；可省略计算机名，也可明确保留 |
| 仅叫 Hermes Bot、Grok Bot、GPT Dot、Assistant 等默认名，或独特身份未核实 | 默认名/产品短名 + 实际模型标识 PC:实际计算机名 |

“具备独特名称”指本来就有可追溯身份的 Bot 实例，不是产品品牌，也不是为了省略计算机临时起名。本地 Agent 有昵称仍按本地 Agent 规则；不能把 Codex/Cursor 当作独特 Bot 名豁免。

Windows 可用 PowerShell `[Environment]::MachineName` 查询，其他环境用实际执行主机的 `hostname`；生成器默认调用当前 OS 的 `socket.gethostname()`。远程/容器与桌面主机不同，必须说明实际执行环境；若由已核的远端宿主执行，可用 `--computer-name` 提供真实查询值，不能凭用户名、项目名、IP或历史印象推断，也不伪造未知值。查询失败就先核实身份，不静默生成缺机器的本地 Agent 首行。

只追加所需的计算机名称，不顺带记录账号、地址、路径或凭证；不更改全机计算机名、邮箱绑定或历史提交。执行者显示名与平台登录账号分开，见下节；身份记录不是密码学认证。当前用户/仓库明确约定的标题前缀优先，但不能绕过公开脱敏边界。

### 自己的名字、Git 显示名与 GitHub 账号

- 私有提交消息写实际产品短名或本人 Bot 名，不用共用 GitHub 账号名代替。私有的新 Agent 原创提交，其 Git author/committer 显示名也应使用实际执行者的产品短名或本人名字；它们与用于认证、邮箱关联的 GitHub 登录账号是不同字段。
- 在已授权的当前提交使用单次 Git 身份覆盖（例如 `git -c user.name="<真实执行者名>" commit …`），或确属该执行者专用且获授权的仓库局部设置；先核真实身份和有效邮箱。宿主注入的 `GIT_AUTHOR_NAME` / `GIT_COMMITTER_NAME` 等环境字段可能优先于 `-c user.name`：提交前用 `git var GIT_AUTHOR_IDENT` / `git var GIT_COMMITTER_IDENT` 核有效值，提交后回读实际 author/committer；有冲突只在已授权的当前进程内处理，不误改原作者。不能修改全局配置、GitHub 账号或邮箱绑定，不编造邮箱，不在姓名中塞型号或PC；平台可能仍通过邮箱显示关联账号，这不等于Git作者名未生效。
- 本人只是代提交、转移/cherry-pick别人原作或混合既有人工贡献时，保留真实作者及原贡献，不能把他人的 author 改成自己。继承的人类约定按混合规则说明；不重写旧提交。
- 公开目标沿用仓库批准的非敏感作者身份/邮箱，不为了追溯额外暴露内部Bot、模型或计算机名；如现有元数据不宜公开，按授权调整当前提交后再发。首行生成器只生成消息，不自动设置 Git author/committer、账号或邮箱；`human_commit_name` 也不是修改 Git 作者的开关。

## 如何识别混合贡献

1. 对照开工基线、已知人工改动与 **staged diff**，读取变更块及所在函数/类型的必要上下文。检查历史 `LD:` / `LD：`、当前自定义人类标识，以及有来源的既有人类标记；单纯字符串 `LD`、仓库名或文件里远处无关标记不算证据。
2. 本次变更包含人类注释，或修改了该注释明确关联的接口、函数、实现/设计约束时，私有目标使用混合首行，公开目标只在正文保留不暴露身份的贡献范围。**注释本身没变、关联代码改变，也不能把继承的人类贡献全算作 AI 独创。**解决节可写“人类：既有约定/实现；Agent：本次适配”，不能反过来声称人类这次亲自敲了所有代码。
3. 对已确认的人类未提交代码，即使未带标记，也应按真实贡献保留署名。保护标记是归属/约束线索，不等于已人工审查，不凭 Git author 或单个关键词计算贡献比例。
4. AI 不得冒写或改写人类标记来制造“人类参与”。AI 自己产生的此类改动默认阻断；混合首行不能把未经授权的人工保护行改动洗成合法。已确认来源且属于本次提交授权的人工改动可保留原文混合提交，不因存在标记就重复索要逐行审批；来源或纳入范围不清时先核实，不能直接全算 AI，也不能顺手纳入无关人工工作。

## 格式与工具

- 三段按顺序，**首行与问题、解决节之间留空行**，否则 Git 会把连续正文并入标题。问题/解决标签使用全角冒号、正文中文；`PC:` 固定使用ASCII冒号，必要命令、API、路径和实际模型标识保持原样。
- 私有目标写本人产品短名或真实 Bot 名、精确模型及适用的 `PC:`，混合提交的人类名仍保留。不把审查者身份记成实现者；未确认型号先查证，不冒用示例型号或以厂商名兜底。
- 私有首行必须有 ` | ` 后的具体摘要；公开首行只写摘要。测试、文件范围、风险、未验部分放解决节，不用空泛“优化一下”，不以 `fix:`/厂商前缀替代该格式。
- 先简后繁：首行概括主要结果；问题节先说用户遇到什么；解决节先总述，再按实际改动、验证、保留边界和未验收项展开。小改动不凑长篇，大改动不只写“修复/优化”，不把计划写成成果。
- 生成器只改变**本次提交消息**；私有新提交的作者显示名由执行者按上节在当前授权范围设置，不虚构 Co-authored-by 邮箱、不重写旧提交，不把显示名当成版权转让。

可通过终端工具运行首行生成器（从本技能目录执行）。**必须显式传 `--visibility public|private`，这是调用方已核目标的声明，不是自动查询或推送批准。**未传/未知值拒绝，不静默走旧私有格式；原有调用须补该参数。

公开目标仅需已脱敏摘要：

```sh
python -B scripts/maintain.py commit-header --visibility public --summary "补充公开提交隐私规则"
```

公开模式只返回 `header` 与 `visibility`，不读取显示名配置或OS主机名，不回显配置/本地路径。旧调用夹带的身份选项忽略且不输出；不要主动传秘密给命令行。摘要由调用方检查，工具仅拒绝常见身份字段结构，**不是通用脱敏器**，不会替你识别任意证件号或密钥。

已核私有目标（替换实际身份与摘要）：

```sh
python -B scripts/maintain.py commit-header --visibility private --mixed-human --client "<实际客户端名>" --model "<实际模型标识>" --summary "<具体改动摘要>"
```

已核实的独特命名 Bot 使用：

```sh
python -B scripts/maintain.py commit-header --visibility private --bot "<实际独特Bot名>" --named-bot --model "<实际模型标识>" --summary "<具体改动摘要>"
```

JSON 的 `header` 就是可采用的首行。以下选项说明仅适用于私有模式：纯 Agent 改动省略 `--mixed-human`；`--client` 与 `--bot` 二选一，均省略时兼容保留模型与 `PC:`，但已知执行者的新提交必须显式填写自己的产品短名或Bot名，不能把兼容路径当省略身份的默认。已有 `--bot` 调用继续有效；只有真实独特 Bot 显式传 `--named-bot` 才省略机器，`Codex`及两种旧产品名均不得冒充豁免。名单不是完整身份库，调用方仍须核实。`--computer-name` 是本次已核主机值，不保存到偏好；独特 Bot 也可用它保留机器信息。

私有模式读取当前显示名和需要的OS主机名；两种模式均**不自动判断贡献、不暂存、不 commit、不 push**；`--mixed-human` 与 `--named-bot` 是调用方已核实的声明，不是安全审核或身份认证。完整提交仍须补齐问题/解决两节；输出字段含换行/分隔符或无有效机器名时拒绝，不编造兜底值。

## 提交与推送前

1. 核本次任务的提交/推送权限、分支和实际目标可见性，按上文选择公开或私有格式；只暂存授权范围，不为清空工作区混入人工未完成内容。公开交付必须完成下节隐私检查。
2. 核人类保护行与关联代码的 staged 变更，按上述规则选择纯 Agent / 混合格式；保护历史 `LD:`、自定义人工标记和 `[debug]`。
3. 按[强制注释验收](comments.md#执行委派与提交验收)检查本次新写和改动的函数：有效头部文档、核心原理行注释及语义一致性；本次缺项先补好，未改动旧函数的注释缺口留到专门打扫，不阻断本次提交。编译通过不能代替注释检查。按[代码格式整理](contract.md#代码格式整理)核本次改动已整理、未改变原编码与换行、无全文件重排；改了插件原件的须已标记并在插件目录外登记，见[插件纯净与必要改写](contract.md#插件纯净与必要改写)。再核配对接口、Base 扩展点、命名空间、插件隔离、Inspector Tooltip、模块索引、序列化/GUID 和兼容边界。
4. `.cs` 改动过含 Editor 路径的语法检查；缺引用不冒充语法错误，也不冒充编译成功。运行时、Unity 编译、Play、视听体验分别报告真实结果。
5. 私有格式核实际客户端/Bot/模型身份及计算机查询来源；公开格式核整个消息没有身份回填。读 staged diff 和最终提交消息；提交后回读 commit，获准推送后回读精确远端 SHA。不得强推、自动 stash/reset/clean 或改写旧提交解决普通问题。

## 公开前隐私检查与脱敏

这是实际 commit/push 前的必要步骤，不是安装后全机巡检。只读核本次将公开的项目内容及历史；发现问题在已授权范围内最小脱敏，涉及未获准的人工文件、合同或业务数据则暂停相关公开动作，不能为了发出PR先泄露。

1. **检查完整公开载荷**：提交前看 staged 文件内容及最终消息；推送前看相对准确目标基线的全部待推送提交（含中间版本、删除文件、提交消息和 author/email 等元数据），首次公开或私转公还须核所有将暴露的历史、分支及标签。已有公开仓库的日常增量只核本次新增公开范围及相关风险线索，不每次重扫无关历史。连带检查 PR 标题/正文/附件、README/共享记忆、配置、示例、日志、截图、二进制/压缩包；无法可靠查看的相关载荷标未核并暂缓，不以纯文本扫描代替。
2. **识别个人与企业隐私**：证件号、个人联系方式/住址、客户和员工资料、合同/财务/业务内部数据、内部端点与机器/账号信息，以及密码、API密钥、token、私钥、证书私钥、连接串、签名下载链接等。按内容和业务语境判断；正常公开API、公开组织名与必要许可来源不机械删除。可以用现有秘密扫描器辅助，扫描通过不能保证无泄漏，不上传到未经授权的在线扫描服务。
3. **真正脱敏且保持可用**：敏感配置改为环境变量或仓库外受控配置，提交不含真实值的示例；文档、日志及图片用明确占位或不可恢复的移除/遮盖，保留必要说明并验证功能/格式。凭据须完整移出，不用部分掩码保留可用片段，不编码/加密后连解密材料一同提交。不要把原值写进提交、PR、删除摘要、测试夹具或公开备份。
4. **历史同样阻断**：`.gitignore` 不会移除已跟踪文件；在后一提交删除秘密，也不会清掉前一提交。发现待推送历史有秘密或应省略的身份段，先停止相关推送，按授权准备干净提交；不能自行强推、重写已发布历史或抹除审计证据。已公开的真实凭据按泄漏处理，安全通知责任人并由有权方撤销/轮换，单纯删文件不算解决；原有非秘密身份记录不因新规则自动批量追改。
5. **复核后再交付**：重新检查脱敏后的 staged 内容、所有新增公开提交和对外说明，保留不含秘密的检查范围、结论及未核项。Git author/email若含不宜公开资料，先按仓库/用户授权配置适当的公开署名（如 noreply），不伪造作者或擅改全局配置。秘密检查与“不记录模型段”是两道独立要求，私有仓库也不是提交真实密钥的理由。

## 推送后与合并后的用户流程回归

- 推送后确认远端精确SHA，按所属README声明找到 `Agentic/DEBUG.md`，对受影响功能从真实用户入口实际尝试相关流程；记录流程修订、被测提交/制品、实际加载版本、环境、日期、预期/实际、证据和未验范围。
- PR/分支合并后，核合并后的准确结果并对该版本再尝试；分支上通过不能抵扣集成回归。未合并则写未合并，不为了回归自行合并；尚未部署、缺设备/权限或需要危险动作时明确受阻/未验，不暗示业务已可用。
