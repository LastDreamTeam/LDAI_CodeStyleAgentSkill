# 提交、混合贡献与真实交付

本页规定本次提交的身份、贡献和隐私边界，**覆盖一切仓库，与引擎、开发语言、项目规模、是否采用LD架构及共享记忆黑名单无关**。私有身份强制准确；public按默认简化身份或主人明确定制执行。当前用户修正优先；身份字段必须与真实执行者对应，生成器只检验声明与格式，不认证实际模型、推理设置、Bot 资料或提交权限。

## 先核目标可见性

commit 前确认实际推送目标，push 前再核托管平台当前可见性，包括 push URL、fork 与 PR base；不能仅凭仓库名、HTTPS 地址、能否匿名克隆或 `private=false` 推断公开（企业 `internal` 不等于 `public`）。多个目标只要有一个公开，就按公开规则准备。未知/查询失败不默认私有，不生成带身份的首行，不向未核目标推送；企业内部可见性先核其披露规则，未明确时暂停相关项。

### 公开仓库：默认保留简短身份，用户可明确覆盖

公开默认 **Bot 只写本人昵称，Agent 只写精确完整型号，不带推理强度**。默认不附框架、容器、机器名或混合贡献的人类显示名。型号自己的供应商命名空间、版本、大小写和后缀保留；不能把 `GPT`、`Sol`、产品名或 `auto` 当完整型号。

```text
##模型：<精确完整型号或真实Bot昵称> | 补充公开提交隐私规则

##问题：公开提交需要清楚的贡献身份，同时避免泄漏内部资料。

##解决：采用公开默认身份，核对本次公开内容；填写真实验证和未验边界。
```

用户可对公开显示名作明确覆盖，包括完全省略身份。`--public-name` 表达用户指定的公开名称，`--omit-public-identity` 表达用户明确要求只留摘要，两者互斥；不能因为身份尚未核实就擅自选省略。省略后的三段仍用空行分隔：

```text
补充公开提交隐私规则

##问题：用户明确要求本次公开提交省略身份，并保护相关内部资料。

##解决：按要求只留具体摘要及问题、解决两节；记录真实验证和未验边界。
```

公开覆盖只适用于公开目标，**不能弱化私有 Bot/Agent 的必填身份要求**。生成器无法判断用户是否真的授权覆盖，调用方须保留准确依据。用户指定名称仍须为合法单行文本，不借覆盖伪造贡献或塞入敏感资料。

公开 PR 的 merge/squash 消息及继承 Commit 规则的 README/MEMORY/USER/DEBUG 变更记录沿用同一公开选择：默认简短身份；有明确覆盖则遵从覆盖。变更记录仍保留日期、动作、条目标识、原因、验证及非敏感来源，不额外补记内部框架、推理强度或机器信息。混合贡献可用“人类既有约定 / 本次实现”等文字说明，不冒认贡献。必要的合法版权/许可署名保留；不自动改写历史或受保护人工注释。

### 私有仓库：按真实角色与贡献生成首行

私有 **Bot 写 `框架/容器-昵称`，不需要模型和推理强度**；这里的 `框架/容器` 表示填写实际使用的框架或容器名称，不要求把两个名称全部堆上。私有 **Agent 写 `框架 精确完整型号 实际推理强度`**，身份组成部分之间不用 `+`，默认不带机器名。采用尽量短、仍完整准确的写法。

```text
##模型：<框架> <精确完整型号> <实际推理强度> | <本次具体改动短摘要>

##问题：实际症状、需求缺口或根因及影响范围。

##解决：改了什么、为何这样改；验证结果及未验证的边界。
```

```text
##模型：<框架或容器>-<真实Bot昵称> | <本次具体改动短摘要>

##问题：实际症状、需求缺口或根因及影响范围。

##解决：改了什么、为何这样改；验证结果及未验证的边界。
```

本次暂存变更涉及人类标记的注释或其明确关联的代码/设计约定时，使用混合贡献前缀。**仅混合贡献前缀保留既有 ` + `**，后面的执行身份仍按上面的简短规则：

```text
##主人 + 模型：<框架> <精确完整型号> <实际推理强度> | <本次具体改动短摘要>

##问题：实际症状、需求缺口或根因及影响范围。

##解决：说明人类贡献/既有约定与 Agent 本次改动各自的范围；真实验证和未验部分。
```

`主人` 来自本安装的 **`human_commit_name`**，默认“主人”；源码人类标识由独立的 **`human_name`** 控制，默认 `LD`。改显示名为“褪色的梦”后，混合前缀为 `##褪色的梦 + 模型：`，不加 `【】`，也不替换源码里的 `LD:`。设置说明和命令只放在 [README 参数设置](https://github.com/LastDreamTeam/LDAI_CodeStyleAgentSkill#参数设置)。

## 客户端、Bot 与计算机身份

### Bot 与普通工具 Agent 的界限

Bot 指具有**独立身份**、可追溯的人格/身份配置、本人长期记忆及技能资料的实例；它的昵称属于持续存在的身份资料，不能为了缩短提交临时虚构。框架或容器说明它运行于哪里，例如 `Hermes-列克星敦` 是结构示意，不自动证明该实例存在或获授权。

Codex、Cursor、IDE 插件、DeepSeekHarness 等普通会话工具即使临时有昵称，也仍按 Agent 规则写框架、完整型号与实际推理强度。不能靠设置 `--bot` 或 `--named-bot` 冒充 Bot；`Hermes`、`DSH`、`DSH Bot` 等框架名称也不能直接冒充本人昵称。`--named-bot` 仅表示调用方已经核对独立身份和资料，工具不会读取、认证或导出这些私有资料。Bot 运行于哪个产品不自动给它更多权限。

私有 Bot 必须同时提供 `--client` 框架/容器、`--bot` 昵称和 `--named-bot` 声明，二者**可以且应当组合**；不需要 `--model` 或 `--reasoning-effort`，夹带的模型字段不进入 Bot 身份。公开 Bot 默认只需昵称及真实声明，不要求暴露框架。昵称缺失或只给普通工具起别名时，应回到真实 Agent 身份，不猜 Bot 资格。

### 完整型号与实际推理强度

- **真实框架和型号分开**：`--client` 写可辨识的框架/产品短名，不用共用 GitHub 账号代替。`OpenAI Codex` / `OpenAICodex` 显式兼容为 `Codex`，未知框架不盲目缩短。型号不是产品名，不能凭 Codex 推测它背后的模型。
- **先核实际执行值**：依据当前会话、有效宿主配置与执行回执核实完整型号和实际推理强度；路由别名与期望配置未必是最终执行值。`GPT`、`Sol`、厂商名、`auto`、`unknown`、`latest`、缺值和示例占位不能充作已核型号。生成器拒绝若干明显错误，但不维护完整模型目录；字符串通过不等于真实身份已核实。
- **私有 Agent 强度必填**：`--reasoning-effort` 接受实际档位 `none/minimal/low/medium/high/xhigh/max`。真实不支持推理强度控制的运行可明确声明 `none`；它表示已核事实，**不知道强度不等于 none**，不能自动填默认档位。当前运行若使用其他未支持的档位，应报告工具不支持并核实扩展，不伪装成列表中另一档。
- **完整型号不任意修改**：供应商命名空间、版本、大小写、参数标签和连字符后缀原样保留。例如 `vendor/Exact-Model-v2-high` 中的 `-high` 不会被猜成推理档位。通常把型号与强度分成两个参数；若输入完整串 `GPT Sol6.1 xhigh`，同时明确 `--reasoning-effort xhigh`，私有保留原串且不重复追加，公开才剥离这个已明确匹配的空格尾部档位。缺少独立声明或两处档位冲突时拒绝，要求先分清字段。
- **不靠清洗伪造身份**：换行、控制字符、身份分隔符、注入字段和占位文本拒绝，不截断、不自动删字符。当前身份字段不接受 `+` 字符；若某正式型号的真实标识本身含有 `+`，生成器会拒绝而不会擅自删掉该字符变成另一个型号，需据实际标识核实工具适配。此限制不允许用不完整型号绕过。

### PC 仅为显式附加信息

默认不采集、不推断、不输出计算机名。私有提交确需辨认执行主机时可显式传 `--pc`，或使用兼容别名 `--computer-name`，在身份后追加 ` PC:<真实主机名>`。二者同时提供时必须一致。Bot 和 Agent 都可显式附加，不再以具名 Bot 资格决定是否查询主机。

主机值由调用方按需要从真实执行环境核实；远端或容器与桌面主机不同，不能凭用户名、项目名、IP 或旧印象推断。生成器从不调用主机查询，不因缺少 PC 而失败。公开默认不输出这类内部主机字段，旧调用夹带的 PC 参数也不会被回显；公开身份确需特殊内容时由用户明确指定公开名称并完成隐私审查。

只附所需信息，不顺带记录账号、地址、路径或凭证，不更改全机计算机名。身份记录不是密码学认证，当前用户/仓库明确约定的标题前缀不改变真实贡献及隐私边界。

### 自己的名字、Git 显示名与 GitHub 账号

- 新 Agent/Bot 原创提交的 Git author/committer 显示名可复用生成结果的 **`identity`**，与本次可见性和明确公开覆盖保持一致：私有 Bot 是框架-昵称，私有 Agent 是框架、完整型号和实际强度；公开默认是昵称或型号。明确省略公开身份时，空 `identity` 不可用作 Git 空作者，沿用用户批准的非敏感真实作者身份。
- **真实自有邮箱优先**：执行者确有自己合法可用、获准用于当前提交的邮箱时优先使用；没有时沿用获准且有效的现有邮箱，或核实仓库批准的公开邮箱方案。不编造邮箱、不虚构 Co-authored-by、不把测试用 `example.invalid` 当真实邮箱，也不擅自改变账号绑定或全局 Git 设置。平台可能根据邮箱显示关联 GitHub 账号，这与 Git 显示名是不同字段。
- 只在已授权当前提交使用单次身份覆盖，例如 `git -c user.name="<identity>" commit …`，或确属该执行者专用且获授权的仓库局部设置。宿主注入的 `GIT_AUTHOR_NAME` / `GIT_COMMITTER_NAME` / 邮箱环境字段可能优先于 `-c`：提交前用 `git var GIT_AUTHOR_IDENT` / `git var GIT_COMMITTER_IDENT` 核有效值，提交后回读实际 author/committer；冲突只在已授权当前进程内处理，不误改原作者。
- 本人只是代提交、转移/cherry-pick 别人原作或纳入既有人类改动时，保留真实作者与贡献；不能把别人原作 author 改成自己。继承的人类约定按混合规则说明；不重写旧提交。
- 公开目标只用获准的非敏感身份与邮箱，不把省略的内部信息改填到消息正文、trailer、PR、共享记忆或元数据。生成器只返回字符串和结果对象，**不会设置 Git 作者、邮箱或配置**；`human_commit_name` 也不是修改 Git 作者的开关。

## 如何识别混合贡献

1. 对照开工基线、已知人工改动与 **staged diff**，读取变更块及所在函数/类型的必要上下文。检查历史 `LD:` / `LD：`、当前自定义人类标识，以及有来源的既有人类标记；单纯字符串 `LD`、仓库名或文件远处无关标记不算证据。
2. 本次变更包含人类注释，或修改其明确关联的接口、函数、实现/设计约束时，私有使用混合首行；公开采用已选公开身份，并在正文说明人类与 Agent 的贡献范围。**注释本身没变、关联代码改变，也不能把继承的人类贡献全算作 AI 独创。**可写“人类：既有约定/实现；Agent：本次适配”，不能声称人类这次亲自写了所有代码。
3. 已确认的人类未提交代码即使未带标记，也按真实贡献保留归属。保护标记是归属/约束线索，不等于已人工审查，不凭 Git author 或单个关键词计算贡献比例。
4. AI 不得冒写或改写人类标记制造“人类参与”，AI 自己产生的此类改动默认阻断；混合首行不能把未授权的人工保护行改动洗成合法。已确认来源且属于本次提交授权的人工改动可保留原文，不因存在标记就重复索要逐行审批；来源或纳入范围不清时先核实，不擅自纳入无关人工工作。

## 格式与工具

三段依次为首行、`##问题：`、`##解决：`，**段间留空行**，否则 Git 会把连续正文并入标题。标签用全角冒号，正文中文；必要命令、API、路径和完整型号保持原样。首行身份后用 ` | ` 接具体摘要；用户明确省略公开身份时只留摘要。不用空泛“优化一下”，不以厂商前缀替代身份，也不把审查者写成实现者。

先简后繁：摘要概括结果，问题节说明用户遇到什么，解决节展开实际改动、理由、证据、风险和未验边界。小改动不凑长篇，大改动不只写“修复”；不把计划或一次通过写成全部完成。

以下命令从完整技能目录执行。**必须显式传 `--visibility public|private`**，这是调用方已核目标的声明，不是自动查询或推送批准。示意占位须换成真实值，不能直接照抄运行。

```sh
# 私有 Agent：三个身份字段齐全，普通工具昵称不构成 Bot
python -B scripts/maintain.py commit-header --visibility private --client "<真实框架>" --model "<精确完整型号>" --reasoning-effort high --summary "<具体摘要>"

# 私有 Bot：已核独立身份与资料，框架和昵称组合，不需要模型
python -B scripts/maintain.py commit-header --visibility private --client "<真实框架或容器>" --bot "<本人昵称>" --named-bot --summary "<具体摘要>"

# 公开 Agent / Bot 默认身份
python -B scripts/maintain.py commit-header --visibility public --model "<精确完整型号>" --summary "<具体摘要>"
python -B scripts/maintain.py commit-header --visibility public --bot "<本人昵称>" --named-bot --summary "<具体摘要>"

# 只在用户明确要求本次公开覆盖时，二选一
python -B scripts/maintain.py commit-header --visibility public --public-name "<用户指定公开名称>" --summary "<具体摘要>"
python -B scripts/maintain.py commit-header --visibility public --omit-public-identity --summary "<具体摘要>"
```

私有混合贡献追加 `--mixed-human`，必要时显式追加 `--pc "<已核主机名>"`。公有默认不需要推理档位；若型号输入混有末尾档位，按上文规则明确拆分或提供一致的 `--reasoning-effort`。`--public-name` 和省略开关不适用于私有，不能用来绕过缺失身份。

[独立模块](../scripts/commit_identity.py) 可直接 import：`commit_header(config, model, bot, summary, *, mixed_human=False, client='', named_bot=False, computer_name=None, visibility=None, reasoning_effort=None, public_name=None, omit_public_identity=False, pc=None)` 返回首行字符串；`commit_result` 同签名返回 `header/identity/visibility`；`commit_identity` 接受 model、bot 和相应身份选项，返回身份字符串。三个函数都无文件、主机或 Git 副作用。

CLI 公开模式只返回上述三个字段，不读取显示名配置、本机身份或本地状态路径。私有模式保留已有配置诊断输出，混合人类名由当前安装配置传入。两种模式均**不自动判断贡献、不暂存、不 commit、不 push**；`--mixed-human`、`--named-bot`、可见性和公开覆盖是调用方声明，不是安全审核或身份认证。生成器拒绝部分明显身份注入，**不是通用脱敏器**，不会替你识别任意证件号或密钥。

## 提交与推送前

1. 核本次提交/推送权限、分支、目标可见性及公开覆盖依据，只暂存授权范围，不为清空工作区混入人工未完成内容。公开交付完成下节隐私检查。
2. 核人类保护行与关联代码的 staged 变更，按真实贡献选择前缀与正文；保护历史 `LD:`、自定义人工标记和 `[debug]`。
3. 在项目已采用的源码开发规范范围内，按[强制注释验收](comments.md#执行委派与提交验收)核本次新写和改动函数的有效头部文档、核心原理行注释及语义；本次缺项先补好，未改动旧函数缺口留到专门打扫。编译通过不能代替注释检查。按[代码格式整理](contract.md#代码格式整理)核本次范围、原编码与换行，避免全文件重排；改插件原件须按[必要改写规则](contract.md#插件纯净与必要改写)标记并登记。再核配对接口、Base 扩展、命名空间、插件隔离、Inspector Tooltip、模块索引及序列化/GUID 兼容。
4. `.cs` 改动过含 Editor 路径的语法检查；缺引用不冒充语法错误或编译成功。运行时、Unity 编译、Play 和视听体验分别报告真实结果。
5. 私有核 Bot 独立身份或 Agent 完整型号/实际强度；有 PC 时核显式来源。公开核默认精简身份或用户明确覆盖，并检查消息及元数据没有额外回填内部资料。读 staged diff 与最终消息，提交后回读 commit；获准推送后回读精确远端 SHA。不得用强推、自动 stash/reset/clean 或改写旧提交解决普通问题。
6. 若业务或插件已声明推送依赖某技能版本及健康状态，使用 `python -B scripts/maintain.py health --require-healthy --min-version "<该业务实际要求的版本>"`，核实际退出码并按依赖约定阻止相关 push。版本不符、dirty 或其他失败不能报通过；不健康也不等于所有规范都不可参考，不扩大为无关业务停工。健康字段、判定及退出码以[维护接口说明](maintenance.md)为准；此检查不代替业务测试或推送授权。

## 公开前隐私检查与脱敏

这是实际 commit/push 前的必要步骤，不是安装后全机巡检。只核本次将公开的项目内容及历史；问题在已授权范围内最小脱敏，涉及未获准人工文件、合同或业务数据时暂停相关公开动作，不能为了发出 PR 先泄露。

1. **检查完整公开载荷**：提交前看 staged 文件及最终消息；推送前看相对准确目标基线的全部待推送提交（含中间版本、删除文件、消息和 author/email 元数据）。首次公开或私转公还须核将暴露的历史、分支及标签。日常增量只核新增公开范围和相关风险线索，不重扫无关历史。连带检查 PR 标题/正文/附件、README/共享记忆、配置、示例、日志、截图、二进制/压缩包；相关载荷无法可靠查看时标未核并暂缓，不以文本扫描代替。
2. **识别个人与企业隐私**：证件号、个人联系方式/住址、客户和员工资料、合同/财务/业务内部数据、内部端点与机器/账号信息，以及密码、API 密钥、token、私钥、证书私钥、连接串、签名下载链接等。按业务语境判断，正常公开 API、公开组织名和必要许可来源不机械删除。可用现有秘密扫描器辅助，但通过不能保证无泄漏，不上传到未授权的在线服务。
3. **真正脱敏且保持可用**：敏感配置改为环境变量或仓库外受控配置，提交不含真实值的示例；文档、日志、图片用明确占位或不可恢复移除/遮盖，保留说明并验证格式/功能。凭据完整移出，不用部分掩码保留可用片段，不把编码/密文与解密材料一起提交。原值不得写进消息、PR、删除摘要、测试夹具或公开备份。
4. **历史同样阻断**：`.gitignore` 不移除已跟踪文件；后一提交删除秘密也不清除前一提交。待推送历史有秘密或违背本次公开选择的内部身份资料时，先停止相关推送，按授权准备干净提交；不自行强推、重写已发布历史或抹除审计证据。已公开真实凭据按泄漏处理，由有权方撤销/轮换，单纯删文件不算解决；原有非秘密身份记录不因新规则自动批量追改。
5. **复核后再交付**：重新检查脱敏后 staged 内容、新增公开提交及对外说明，保留不含秘密的检查范围、结论与未核项。作者/邮箱有不宜公开资料时，按用户/仓库授权核实适当公开署名及真实可用邮箱，不伪造作者或擅改全局。秘密检查与公开身份选择是独立要求，私有仓库也不是提交真实密钥的理由。

## 推送后与合并后的用户流程回归

- 推送后确认远端精确 SHA，按所属 README 找到 `Agentic/DEBUG.md`，从真实用户入口尝试受影响流程；记录流程修订、被测提交/制品、实际加载版本、环境、日期、预期/实际、证据及未验范围。
- PR/分支合并后核准确结果并对该版本再次尝试；分支通过不能抵扣集成回归。未合并就写未合并，不为回归自行合并；未部署、缺设备/权限或需要危险动作时明确受阻/未验，不暗示业务已可用。
- DEBUG 来自有来源的用户流程和真实经验，不是自动部署或危险操作授权；失败保留证据，不靠降低预期、清错或改流程洗绿。仅文档改动按实际影响验证声明、链接和工具，不机械跑无关产品全套测试。详情见[共享上下文与 DEBUG](directory-context.md#推送后与合并后的回归)。

```text
##褪色的梦 + 模型：<框架或容器>-<真实Bot昵称> | 按人类约定修复重复实例

##问题：便捷入口未遵守人类标记的常驻实例复用约定。

##解决：保留人类已有约定与实现边界，Bot 调整便捷入口以复用绑定实例。

```

协作任务交代最新可证基线与互不冲突的写入范围，避免多写者覆盖；合并保持真实贡献及对应公开/私有身份规则。报告完成以人类验收目标为中心，不能用测试数量或文档数量代替功能可用。
