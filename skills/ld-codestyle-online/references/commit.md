# 提交、混合贡献与真实交付

## 首行按实际贡献选择

纯 Agent 改动沿用：

```text
##模型：bot名称（若有） + 模型具体型号 | 本次具体改动短摘要

##问题：实际症状、需求缺口或根因及影响范围。

##解决：改了什么、为何这样改；验证结果及未验证的边界。
```

本次暂存变更涉及人类标记的注释或其明确关联的代码/设计约定时，不把整体成果完全记成 AI 自己的，使用混合贡献格式：

```text
##主人 + 模型：bot名称（若有） + 模型具体型号 | 本次具体改动短摘要

##问题：实际症状、需求缺口或根因及影响范围。

##解决：说明人类贡献/既有约定与 Agent 本次改动各自的范围；真实验证和未验部分。
```

其中 `主人` 来自本安装的 **`human_commit_name`**，默认值是“主人”；代码人类标识由独立的 **`human_name`** 控制，默认 `LD`。修改显示名为“褪色的梦”后，同一混合首行变为 `##褪色的梦 + 模型：…`，**不加 `【】`**，也不把源码里的 `LD:` 替换成网名。设置说明和命令只放在[README 参数设置](https://github.com/LastDreamTeam/LDAI_CodeStyleAgentSkill#参数设置)。

## 如何识别混合贡献

1. 对照开工基线、已知人工改动与 **staged diff**，读取变更块及所在函数/类型的必要上下文。检查历史 `LD:` / `LD：`、当前自定义人类标识，以及有来源的既有人类标记；单纯字符串 `LD`、仓库名或文件里远处无关标记不算证据。
2. 本次变更包含人类注释，或修改了该注释明确关联的接口、函数、实现/设计约束时，使用混合首行。**注释本身没变、关联代码改变，也不能把继承的人类贡献全算作 AI 独创。**解决节可写“人类：既有约定/实现；Agent：本次适配”，不能反过来声称人类这次亲自敲了所有代码。
3. 对已确认的人类未提交代码，即使未带标记，也应按真实贡献保留署名。保护标记是归属/约束线索，不等于已人工审查，不凭 Git author 或单个关键词计算贡献比例。
4. AI 不得冒写或改写人类标记来制造“人类参与”。AI 自己产生的此类改动默认阻断；混合首行不能把未经授权的人工保护行改动洗成合法。已确认来源且属于本次提交授权的人工改动可保留原文混合提交，不因存在标记就重复索要逐行审批；来源或纳入范围不清时先核实，不能直接全算 AI，也不能顺手纳入无关人工工作。

## 格式与工具

- 三段按顺序，**首行与问题、解决节之间留空行**，否则 Git 会把连续正文并入标题。使用全角冒号、中文正文；必要命令、API、路径和实际模型标识保持原样。
- Bot 存在就写真实名字；没有则仅省略 Bot，混合提交的人类名仍保留。不能用 `AI`、提供商品牌、`Codex` 或 Bot 名字代替精确型号，也不把审查者身份记成实现者。
- 首行必须有 ` | ` 后的具体摘要。测试、文件范围、风险、未验部分放解决节，不用空泛“优化一下”，不以 `fix:`/厂商前缀替代该格式。
- 署名只改变**本次提交消息**，不改 Git 的 author/email、不虚构 Co-authored-by 邮箱、不重写旧提交，不把显示名当成版权转让。

可通过终端工具运行首行生成器（从本技能目录执行；替换实际身份与摘要）：

```sh
python -B scripts/maintain.py commit-header --mixed-human --bot "<实际Bot名>" --model "<实际模型标识>" --summary "<具体改动摘要>"
```

JSON 的 `header` 就是可采用的首行。纯 Agent 改动省略 `--mixed-human`；没有 Bot 省略 `--bot`。此命令读取当前显示名，**不自动判断贡献、不暂存、不 commit、不 push**；`--mixed-human` 是 Agent 已核对上文证据的声明。它不是安全审核或人工贡献的证明，完整提交仍须补齐问题/解决两节。

## 提交与推送前

1. 核本次任务的提交/推送权限、分支和远端；只暂存授权范围，不为清空工作区混入人工未完成内容。
2. 核人类保护行与关联代码的 staged 变更，按上述规则选择纯 Agent / 混合格式；保护历史 `LD:`、自定义人工标记和 `[debug]`。
3. 核配对接口与 Base 扩展点、XML 文档、命名空间、插件隔离、Inspector Tooltip、模块索引、序列化/GUID 和兼容边界。
4. `.cs` 改动过含 Editor 路径的语法检查；缺引用不冒充语法错误，也不冒充编译成功。运行时、Unity 编译、Play、视听体验分别报告真实结果。
5. 读 staged diff 和最终提交消息；提交后回读 commit，获准推送后回读精确远端 SHA。不得强推、自动 stash/reset/clean 或改写旧提交解决普通问题。

## 混合示例（结构示意，不是已经发生的验证）

```text
##褪色的梦 + 模型：<实际Bot名> + <实际模型标识> | 按人类约定修复重复实例

##问题：便捷入口未遵守人类标记的常驻实例复用约定。

##解决：保留人类已有约定与实现边界，Agent 调整便捷入口以复用绑定实例。
验证：填写真实执行结果；未做的 Unity/画面验收明确列出。
```

派协作任务以最新可证基线创建独立分支，避免多写者覆盖；普通合并保持真实模型/作者说明。报告完成时以人类验收目标为中心，不能用测试数量或文档数量替代功能可用。
