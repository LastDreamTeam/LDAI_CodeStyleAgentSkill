# 强制注释：平时写好，旧账另做打扫

注释是代码交付的一部分，不是可选美化。适用于本技能已采用、当前获授权维护的第一方代码。平时管新写和改动的函数，未改动的旧函数缺注释留到专门打扫；函数头部说明与核心原理实现位置的就地解释**不是二选一**，README、提交消息或任务报告不能代替源码内注释。

## 平时：新写和改动的函数必须带注释

- **本次新写和改动的所有具名函数/方法必须有有效的头部文档注释**，不因 `private`、internal、只有一行、名称清楚或“内部辅助”而省略。覆盖接口声明、抽象/虚/重写方法、显式接口实现、构造函数、析构函数、运算符、Unity 生命周期、事件回调、协程、异步、Editor/测试/样例函数。
- C# 在声明及其特性列表之前使用 `///` XML，至少有非空 `<summary>`，用简明中文说明用途及关键语义；有参数和类型参数时分别用 `<param name="...">` 与 `<typeparam name="...">`，有返回值时用 `<returns>` 解释结果含义。void、构造函数、析构函数不虚填返回项；Task/迭代器说明完成或产出语义。异常、调用前提、副作用、线程/生命周期约束按实际存在情况补 `<exception>` / `<remarks>`，不凭想象编造契约。
- 实现与上级契约确实同义、原文存在且工具能解析时，可以在头部明确写 `/// <inheritdoc/>`（必要时指定准确 `cref`）；不得用它引用不存在的说明、掩盖实现差异，或直接省略本地头部。不同副作用和约束须就地补充。
- 不支持 XML 文档的语言使用其有效原生形式：Java/JSDoc/TSDoc 文档块、Python 函数体首句 docstring、其他语言的文档/行注释。Python 不支持 `//`，使用 `#`；不得为满足形式塞入无效语法。
- C# 局部函数等工具链不接受有效 XML 的位置，使用紧邻声明的 `//` 等有效注释说明；不能制造无效 `///` 或文档编译警告。具名箭头函数/函数表达式同样就近说明；匿名 lambda/内联回调在定义或注册处解释职责，核心逻辑仍须就地说明，不靠改成匿名函数绕过。
- 已有属性/事件的契约文档要求保留；有业务逻辑的访问器在属性/事件头部说明读取、写入或订退阅语义，核心实现处仍加行注释。不为自动属性的每个 `get; set;` 制造重复 XML。

## 平时：核心原理写在实现位置

- **新写和改动函数的核心原理实现位置必须加 `//` 行注释**，不支持该语法的语言用合法等价形式。C#、C/C++、JS/TS 等使用 `//`；不能只给类型或函数头写一句笼统介绍就算补齐。
- 放在对应逻辑块/关键语句之前或旁边，解释“为什么这样做、依据什么规则、维持什么不变量、哪些顺序/边界不能变”。包括实际存在的算法/公式与单位、坐标/时间转换、状态转移、并发与异步、缓存失效、重试/幂等、资源所有权与释放、协议/兼容适配、容错分支和业务阈值。
- 只解释真实逻辑，不要求逐行翻译赋值和循环；简单透传没有独立原理时不硬凑 `//`，但仍必须有函数头部说明。复杂分支不能用“执行核心逻辑”“处理数据”或重复函数名的空话过关。
- 代码语义变化时同步修正相关注释。不能从函数名猜原理、复制不匹配的说明或堆 TODO 占位；未知先查调用、测试和来源，仍无法确认的点如实标未核并阻断该项验收。

## 打扫：旧脚本的缺口另做

旧代码缺注释、旧脚本没按新规，和乱放的旧资料一起归专门打扫，**不是每次任务**都做。打扫在已获准维护的范围内进行，可以分几次补；做不完在原任务记一句“还差哪些”，下次接着清。未改动的旧函数存在注释缺口，不阻断本次提交，也不因此要求把整份脚本重新补一遍。

保护人工未提交内容、`LD:`/自定义人工标记、`[debug]`、版权和准确旧注释；新说明用实际提供方，不冒写人类名。第三方原件和生成代码不直接批量改；不借打扫改变接口、序列化名称、GUID、业务行为或Unity资产，不重启暂停工程。遇到不能安全处理的项，保留原文并记清还差哪些。

## 执行、委派与提交验收

提交前检查本次新写和改动的函数：头部说明、参数/返回语义、核心原理行注释与实际实现一致；缺失、空壳或失实的说明先补好，不能把本次缺口当成旧账。委派同样交代这个范围，主Agent读源码复核，不只接受“已加注释”的回执；编译测试通过不能代替注释检查。

若本轮本来就是打扫，只核已处理的范围，如实记剩余项，不以一部分补好冒称整项目完成。注释更改应通过适用语法/构建检查，不引入无效 XML 或错误参数名；结果记在原任务/PR，不另造报告。

这是 Agent 执行与审查的强制门槛，**不安装 hook/CI**，也不声称能强制所有外部 Agent 遵守。项目已配置的检查器应实际运行，但常见公开API文档告警不覆盖 private 等全部成员，关键词/行数检查不能判断原理解释是否正确，必须保留**语义审查**。引入新的仓库级自动门禁须在相应授权下单独实现验证，不能把本规范或文档契约测试冒充已部署的源码分析器。

## C# 最小示例

以下 `OpenAI:` 仅示例提供方，实际新增注释用真实提供方；保留既有准确注释的归属。

```csharp
/// <summary>OpenAI: 将音频播放时间映射到当前谱面毫秒，补偿输出延迟。</summary>
/// <param name="playbackSeconds">OpenAI: 音频播放时钟，单位为秒。</param>
/// <param name="outputLatencyMs">OpenAI: 输出延迟，单位为毫秒。</param>
/// <returns>OpenAI: 扣除延迟后的谱面时间；起始阶段可能为负。</returns>
private static double ToChartMilliseconds(double playbackSeconds, double outputLatencyMs)
{
    // OpenAI: 延迟意味着玩家更晚听到声音，因此从播放时钟中扣除；保留负值以支持预滚。
    return playbackSeconds * 1000.0 - outputLatencyMs;
}
```

反例：本次新写或改动的 private 函数没有头部说明、空 `<summary/>`、只有“转换时间”却不说明单位/延迟方向、用 README 解释代替实现旁说明，或只处理部分旧函数却声称全项目打扫完毕。
