# 协作契约

本页为基于 LD v6 及人类已确认补充的公开整理。以当前请求、最近工程规则、真实代码与公共/序列化契约为准；不是一次性批量重构授权。

需要裁决时按[交互询问与安全续行](interaction.md)区分工具类Agent与Bot：前者只在当前授权宿主/终端询问，后者在相关聊天渠道询问，不跨其他电脑弹窗。未回答先评估原授权内安全自主，不能安全决定的项留到收尾集中问，继续无依赖的其他内容；不全任务中止、不以沉默替代批准。

## 模块结构与控制边界

```text
<Module>/Scripts/
  I<Feature>ManagerBase.cs
  <Feature>ManagerBase.cs
  README.md                  区域声明与共享记忆入口
  Agentic/
    MEMORY.md                scope=所属README区域，非仅Agentic
    USER.md                  用户持久要求与业务意图
    DEBUG.md                 用户操作与正确测试流程
    <Feature>Manager.cs
  Sample/ 或独立 Demo 入口（按需）
```

配对接口取 Base 类型的精确名称，包含 `Base` 后缀。接口仅放所有实现必需的契约，可以从小甚至空开始；不为未来猜测堆成员。使用无方法体声明，避免不必要的默认接口实现。Base 实现接口，可加必要 protected/virtual 扩展面和简单兜底。初建后配对接口变更须人类或明确授权的架构负责人裁决；当前任务或既有项目授权已明确的裁决无需重复审批。普通接口按工程范围审查，不套一刀切审批；可回档不替代依赖核查或新增授权。

Base 可迭代，不是人工审过的证明。应供派生调整的状态、属性后备、联动转换使用受控 protected setter/方法或 virtual；临时计算、内部缓存、不宜破坏的不变量保留 private。不得迫使派生用反射、复制状态、粘贴整段 Base 绕过契约。

Base/配对接口的属性至少有一份有效 XML 说明，优先放接口；同语义实现可 `<inheritdoc/>`。本次新写和改动函数的头部文档及核心原理就地行注释为[强制要求](comments.md)，包括 private 与派生实现；未改动旧函数的注释缺口留到专门打扫，不阻断本次提交。事件说明用途、约束与生命周期；派生实现对外有用的属性也宜说明。

Agentic 目录权限继承父模块，不能跨越接口、序列化或兄弟模块边界。AI 非 Base 实现默认使用 `.Agentic` 命名空间，包含样例和 Editor 工具；复合业务、独立小脚本等有合理例外时说明，避免无意义包装。

## 目录与职责

- `Assets/Core`：可提取、业务轻的能力模块，附最简单的 Demo/使用入口。
- `Assets/Scripts`：跨模块入口、Model 和全局业务编排，不堆特定模块内脏活。
- `Assets/LastDream/Core` / `Assets/LastDream/Scripts`：混合工程中的隔离区或尚未提升到正式结构的实验能力，也是合法布局。
- 两套根依据现有所有权、成熟度和将来提取边界选择，不为美观互相搬迁。
- 模块内按需放 `Scripts`、`Resources`、变种和 Sample，不机械生成空目录。
- Base/配对接口控制区的README声明 `Agentic/MEMORY.md` / `Agentic/USER.md` / `Agentic/DEBUG.md` 的实际入口和负责路径。平时记东西放所属 README/Agentic；平时，一条坑记在出事那块目录自己的 README/Agentic 里。**致命级例外优先**：死机、崩溃、掉数据、工程/存档损坏，要往外挪到「凡是动这块东西的人都得先看」的那一份文件（含它的索引）；XR 就是 XR 那套文件里最外面的那一份，不是项目根，也不是只留在出事那个子目录。条目标注「死机级」，带触发条件和一手证据（版本/提交）。README 是唯一索引，按需读取相关记忆，不复制正文、不扩大权限；旧的乱放资料另做打扫，见[目录记忆](directory-context.md)。历史人类Readme仍受保护，不制造大小写冲突。
- README/MEMORY/USER/DEBUG及同类文件各自的头部须有自足的基础说明，不能只在README写一次或只放技能链接。直接打开任一文件的陌生Agent，也能知道职责、持久共享属性、实际scope与所属入口、读写维护和权限边界；旧文件缺口在打扫时补齐，保留有效正文、来源和meta，不借此接管人工资料。
- 工作会话发现或用户反馈的复发缺陷，尤其Git历史曾修过时，先核旧提交/diff及适用版本；在已验证修复后更新正确关联层级的持久条目。DEBUG可保存缺陷与防复发完整正文，独立机制/经验归MEMORY并互链，不为文件名抄双份。阶段性/番茄切片成功修复可记录并标剩余范围；不收未验证半途尝试或无价值废弃方案，不以记录代替修复，详见[修复经验闭环](directory-context.md#复发缺陷的修复经验闭环)。
- `Agentic.md` 的模块索引职责收敛到所属 `README.md`，不再新建或续写双套正文；保留 `Agentic/` 目录与 `AGENTS.md` 的独立宿主职责。打扫时在授权区域保全旧内容、来源、相对链接和Unity meta，再停用旧入口；短期兼容仅指路并列退役条件，有阻断记一句还差哪些，不以新增README冒称完成，见[收敛步骤](agentic.md)。
- 美术源资料是长期资产，不擅自清理。Git/LFS 门槛按实际远端限制检查，不默认忽略整份美术库。
- 不因为插件“不整齐”就搬目录；核 GUID、asmdef、Resources、原生依赖后优先项目侧 wrapper/adapter，不改第三方原件。

## Model / Manager / ViewModel / View

默认调用关系：`Model/facade → Manager → ViewModel → View → Unity 可见对象`。

- Model 汇聚方便人类使用的业务动词和合理全局耦合；复用现行单例/facade，不为新功能重复造一套。
- Manager 管当前实现、创建/切换/显示/隐藏/释放与少量稳定 API；需要时可暴露具体 ViewModel，不强做无限转发。
- ViewModel 管不可见状态、规则、时序和输入解释；绑定和解绑匹配模块生命周期。
- View 管显示对象、UGUI、序列化引用、渲染和呈现事件，不反向承接业务决策。
- 单一机械行为/硬件/变换可用 Controller，不为一段小功能强造 MVVM。`View` 不泛指一切可见行为。
- Manager 挂父对象，名称体现业务及 `Manager`/`Mgr`；View/ViewModel 尽量同挂业务命名子对象，避免用脚本列表拼名字。
- Demo 是教学和最小验证场景，宜有独立同用途根对象，不默认塞成 Manager 的子业务，更不能把调试台词/自动运行一起带到成品。

## Core 双入口与变种

- **InstanceMode**：单例/Model 便捷访问，用于临时、调试、小场景；合理延迟查找和缓存，保留 Release，不要求普通使用者先注册/注销。
- **PrefabMode**：显式放置或实例化具体实现，适合主要场景、常驻模块、编辑态查看与调参。调用业务持显式引用，不靠全局搜对象隐去所有权。
- 通常支持两者但复用能力，不复制算法；特殊模块按实际需要。不要触发单例 getter 再造第二个常驻对象。
- 成品挂具体派生脚本，不把 Base 当成品。变种目录代表皮肤/实现，不把轨数、外形或 UI 年代写死成模块本质限制。
- 不预先承诺完全无单例依赖，也不擅自为了理论纯净强上 IoC/UPM。

## C#、Inspector 与文档

- 类型/方法/公开成员 PascalCase。长生命周期字段可用 `m_PascalCase`；保留既有一致的下划线风格，不无事批量改名。
- 序列化字段、GUID、数据键、公开 API、生命周期和兼容拼写不可只为风格更改；确需迁移须有授权与兼容验证。
- Inspector 可编辑字段必须有简洁中文 `Tooltip`；`Header`/`Range`/`Min` 不替代说明。私有/受保护字段加 `[SerializeField]`，外部只读时提供只读属性。
- 新写和改动的函数头部必须写有效 XML/原生文档，核心原理实现位置必须写 `//` 或合法等价注释，按[强制注释与专门打扫](comments.md)执行。写“为什么、时序、生命周期、边界”，不堆逐句翻译；新源码注释采用实际提供方标记，不冒写人类名。“有维护价值”是质量要求，不是省略必填注释的借口。
- P1/P2 等计划编号不是永久业务术语。若保留，每个相关 class 头部 XML 就地定义含义及计划名称/日期/版本，不能仅扔 README 链接或猜编号意义。
- 保护准确旧注释、人工标记和 `[debug]`。确认失实且在授权范围的普通注释可换为有归属的新解释；不要改写人工注释后假装仍由人类写。
- 使用参数化共用逻辑、原子 API、小数据类型，避免成对“先检查再确认”的竞争窗口。退订事件、停止协程/计时器、释放对象应有对应生命周期。
- 显式标出时间、输入、音频、动画等关键顺序；Editor 诊断适当放 `#if UNITY_EDITOR`，必要运行告警保留。

## 修改、迁移与验证

先捕获 Git 分支/HEAD/脏状态，读取相关 Base/配对接口、活跃实现和 Core 索引链。动手前按改动影响核真实入口、直接依赖与受影响调用者、装配方式、公共/序列化契约和生命周期，确定最小验证入口与可恢复边界。局部实现小修只需相关调用链；涉及公共契约、跨模块或共享资源时再扩展调查，不要求每次建立全仓依赖图。范围外重要问题合并简报，不把原任务变成全仓治理。

记忆和索引须回核当前代码及版本。未搜到引用、缺包导致无法编译或缺设备导致无法验证，均不能证明依赖不存在；不要为消除眼前错误删引用、加替代桩或另造架构。未知先沿实际调用和配置定向补证据；仍不足时仅暂缓依赖该判断的改动，继续无依赖且已授权的工作。只有确需新裁决才询问，不把普通调查交给用户审批。

委派给子Agent或Bot时，交代明确任务/文件范围、真实分支/提交及相关脏状态、已核依赖/接口约束、未知项和验收标准；接手者核对实际现场，不把收到的摘要当事实。主Agent对整合diff、实际依赖及受影响流程负责复核，不能仅凭各子任务声称完成就合入。项目经理、主策或队友等头衔本身不授予架构裁决权；已有明确授权沿用，不机械追加审批。

历史项目是行为和素材参考，不是架构目的地。先找现行入口，迁移缺失能力，不用旧代码覆盖更成熟的实现；记录来源、依赖与省略项，先最小 Demo 再业务接入。保护手工内容、玩家数据和未保存的 Unity 现场。Unity 场景/预制件通过合法 Editor 工作流调整，不直接手改 YAML。

`.cs` 先过含 Editor 路径的语法检查，依赖缺失单列；随后项目编译、场景/样例运行和功能体验按层验收。截图、听音、交互、实例唯一性等需各自真实证据，不能用对象存在或自动跑分代替。没有可用检查器/Editor 就明确缺口，不假绿。
