# LD CodeStyle Online

让人类通过 Markdown、自然语言和小而清楚的代码契约表达创意、设计与边界；Agent 承接可替换的实现与验证。**泛用支持是发展方向；目前主要针对并适用于 Unity 重型项目，暂不保证其他场景的功效。**跨宿主可安装或用户明确采用部分规则，不等于跨项目场景的效果已验证；不是所有工程的强制模板。本在线版基于 LD v6 实践整理，独立版本 **0.4.0**，不与旧版叠加执行。

本技能首先约束开发规范、习惯与风格，相对面向更多放权给 AI 的 Solo 开发者和希望减少代码失控的新手；不保证适合所有人，保障目标仍在完善、效果可能有限，不能代替测试和必要的人类判断。

## 何时启用

1. Unity 工程须同时存在 `Assets/` 和 `ProjectSettings/ProjectVersion.txt`。用户明确采用本技能，或工程一方源码已有 `LastDream` 命名空间、LD 协作约定时，对相应一方代码启用。仅安装技能、第三方目录同名或普通 Unity 工程本身不构成采用。
2. **非 Unity 工程绝不自动启用。**用户必须明确要求使用，再核该语言/架构是否支持接口、抽象类、面向对象和替换实现等所需特性。仅应用确认适配的部分，跳过 Unity 专属结构、Inspector 和资产规则。若不适配，说明具体原因，不强造 OOP 层。
3. 当前请求和最近工程规则优先；技能不是扩大任务、提交、发布或重构的授权。第三方原插件、生成代码和无关工程不受本技能接管。

## 开工入口

- 读 [协作契约](references/contract.md)；读最近 `AGENTS.md`、模块说明、真实 Git 分支/HEAD/脏状态以及目标 Base/接口和活跃实现。按改动影响核真实入口、直接依赖与受影响调用者、装配/生命周期及验证入口；缺失上下文先定向补证据，不凭旧记忆、未搜到引用或编译缺包改写架构，也不为小修调查全仓。
- 处理目标路径内的脚本或资产前，按[目录共享上下文](references/directory-context.md)从所属区域 `README.md` 的声明读取 `Agentic/USER.md` → `Agentic/MEMORY.md` → 相关 `Agentic/DEBUG.md`，同时检查相关脚本附近的旧记忆位置，避免迁移前漏读；核逻辑作用域和旧入口，不能把物理存放目录当作用域，也不把局部记忆升为全局权限。
- Core 工作另读 [Agentic 模块索引](references/agentic.md)；索引是缓存，不高于源码、序列化契约和当前人类指令。
- 使用终端工具运行 `python -B scripts/maintain.py show`（当前目录为本技能目录；或用脚本绝对路径），读取 `human_name`（默认 `LD`）及 `human_commit_name`（默认 `主人`）。两者分开，配置失败须报告，不覆盖损坏文件，也不猜用户设定。
- **用户要求主动检查时**，按 [维护说明](references/maintenance.md)运行 `python -B scripts/maintain.py check --force`，即刻检查但不改动技能；即使自动更新已开启，单独的“检查”也不是更新授权。
- 开始采用本技能的新任务时运行 `python -B scripts/maintain.py sync --idle`：到设定周期（默认7天）才快速联网检查。**`auto_update` 默认关闭**；返回 `update_confirmation_required` 时简短告知版本并询问是否更新，不自行同意。`not_due` 不重复催问。用户同意本次后才用 `sync --idle --approve-update`；此参数不改变长期开关。
- 仅在用户明确要求时，按 README 的参数说明修改此实例自动更新开关。开启后在处理过程的安全空档直接更新，不再逐次询问。`--idle` 是调用方确认没有任务占用，不是脚本自动探测；无法确认则仅 `check`。用户冻结版本、要求只检查或拒绝更新时，以其要求为准。
- 更新成功后重新读取新版本再开始任务。已进行的工作固定当前规则，不中途更新或因网络失败阻塞业务。此技能不安装后台任务，不意味着所有终端已经接入。

## 用户提到可配置参数时

- “把技能里的 LD/人类注释标识改为某某”指 `human_name`；“把 Commit 里的主人改为褪色的梦/我的网名”指 `human_commit_name`。后者只改未来混合提交的显示名，不连带改前者。
- “检查周期改为N天”指 `interval_days`；“开启/关闭技能自动更新”指 `auto_update`。首次使用不强迫填写；用户没要求就保留默认。示例、引述和普通称呼不是修改授权。
- 先用 `show` 定位当前安装和旧值，再按[README 参数设置](https://github.com/LastDreamTeam/LDAI_CodeStyleAgentSkill#参数设置)中的唯一修改命令入口，最小修改并回读。自然语言已明确字段和新值时直接执行；“改人类名”等语境不明时只确认歧义项。
- 只修改当前安装配置，不批量修改其他副本、源码标记、历史提交、版权来源、人格或 Git author/email。修改注释标识后旧 `LD:` 与已知人工标记仍受保护；配置损坏/非法值不得自行重置。此处只解释含义与安全边界，不重复参数修改命令。

## 人类与 Agent 的控制面

- **配对 Base 接口**是最后的强约束，不是所有 `interface` 都需要人类逐项审批。初建模块时可建立必要的 `I<ExactTypeName>Base`；建立后普通执行 Agent 不随意变更，必要时由人类或项目明确授权的架构负责人裁决。当前任务或既有项目授权已明确的裁决无需重复审批；可回档不替代依赖核查或新增授权。技能不自动任命任何 Bot 为负责人。
- **Base 是软实现层**，实现其配对接口，可由 AI 迭代，也允许人类参考/兜底实现。守住任务范围、公共 API、序列化和生命周期；不机械限制为只能微修。
- **Agentic 是可识别、可替换的 AI 实现边界**，默认就近目录及 `.Agentic` 命名空间。Base、复合业务、临时及明确独立脚本可有合理例外，不为了格式制造空层。
- Core 是带 Demo 的可提取零件库；允许随模块带走的单例工具、Model 集中入口，不提前强推 IoC、注册仪式或全面 UPM 化。
- 常驻业务在编辑态可查看、装配和调整。按需并存便捷的 InstanceMode 与显式 PrefabMode，两者复用同一能力；常驻实例不能因访问单例又偷偷造一份。成品挂具体派生实现，不以 Base 充当成品。

## 目录级共同记忆与用户意图

- 在实际 Base/配对接口控制区域保留 `README.md`，声明 `Agentic/MEMORY.md`、`Agentic/USER.md`、`Agentic/DEBUG.md` 的职责与入口；其他同类共享记忆正文也集中在 Agentic。目录不必字面叫Base，既可能是模块根也可能是Scripts。
- 采用本版规范后，适用区域内**既有共享记忆也必须迁移**到其Agentic，**不是仅新建文件**使用新布局；搬迁保全内容与原作用域。安装/更新技能不触发全机或全仓扫描；在已采用规范且本轮获授权写维护触及的责任区域，主动完成可安全保全的旧记忆迁移，无须逐文件重新请示。只读不搬，明确采用/迁移任务完成其授权范围；真实冲突只暂停冲突项，明确记迁移未完成和下一责任，不把旧布局留成永久例外，不搬宿主私人记忆。
- **README原有职责与权威索引保持不变**，不随记忆搬迁，不退化为只剩链接的空壳。头部须自足地说明机制、同级区域作用域、MEMORY/USER/DEBUG真实入口及持久知识不可擅删/改作他用，让**未安装本技能**的Agent也能理解，不能只让它去安装技能或读外部链接。
- **每份文件头部都须独立可读，不能只在 README 写一次**：README、MEMORY、USER、DEBUG及同类共享记忆各自用简短基础提示说明本文件职责、持久共享而非临时/私有属性、真实scope与README入口、读写维护和权限边界。让未安装技能、不在舰队/指挥系统的Agent直接打开任何一份也能理解；不得只放链接，提示不充当System Prompt或新增授权。已授权采用/维护范围内的旧文件同样补齐，保留有效正文、历史与meta，不借补头部接管人工文件或扩成全仓重写；见[独立文件头部要求](references/directory-context.md#每份文件头部独立可读的基础说明)。
- 物理位置不改变逻辑范围：上述记忆等同 **README 所在区域**的同级区域上下文，覆盖该区域及后代脚本/资产，**不只管 Agentic、不扩大权限**；不跨到兄弟目录或其他工程。上层共性、下层独立责任分开，跨区域只保留必要路径索引，不复制对方知识正文。
- `MEMORY.md`记录脱敏共有事实/经验；`USER.md`记录有来源的用户持久要求/动态意图；`DEBUG.md`记录用户视角的正确操作和测试流程；README负责区域声明和快速索引。
- **复发缺陷要沉淀有效修复经验**：工作会话发现或用户反馈反复出现，尤其Git曾修过时，核旧提交/diff与实际版本，在已验证修复后更新所属区域MEMORY的同类条目，保留发现、有效修复过程、验证与防复发边界。不收修复中途猜测/废弃方案的无价值流水；阶段性/番茄切片已成功验证即可记录，明确剩余未完成项，不必等整任务结束。旧经验遇反例先标待复核，新修复验证后再更新；见[修复经验闭环](references/directory-context.md#复发缺陷的修复经验闭环)。
- 这是项目共享文档，不是当前Bot的Hermes核心记忆；不同厂商Agent可读可维护。用户要求与Agent推断分开，未来设想不自动变成执行授权，一次性指令不升格为永久规则。
- 本组文档均是**可核参考，非绝对结论**。首次新增解释、经验和意图摘要默认暂定，按证据使用“可能/预计/估计/当前理解”等措辞；准确保留已测观察、真实路径和用户原话，不把事实故意写模糊，也不把一次成功扩成长期保证。
- 条目须经相关远端推送与重复核验：首次相关推送后超过 7 天可复核为持续观察；超过 15 天且多次相关推送（默认至少 3 次独立推送，含首次）、不同时间验证一致且无未解决反例，才可在**再次涉及**时考虑写为限定范围的基本稳定知识。时间/次数不自动证明正确，不为凑条件推送；证据不全则暂定，变化/反例则降级。日期和证据细则见[共享上下文成熟度](references/directory-context.md#参考措辞与知识成熟度)。
- `USER.md` 尽可能保留整理后的用户原话意图，区分摘录与“当前理解”的摘要，保留否定、条件和例外。成熟度约束的是Agent归纳；当前明确用户指令立即按范围生效，不等观察期，也不被旧摘要覆盖。
- 历史 `Readme.md` 默认是人类资料，**不覆盖、不改名、不自动改写**。先核大小写冲突与所有权；采用范围内已有同层 MEMORY/USER 或 AgentDocs 组必须按[兼容迁移规则](references/directory-context.md)保全迁入Agentic、修正声明和链接，不保留双份有效正文；人工冲突只阻断受影响项，不扩成无关工程搬迁。
- 授权写任务中按实际增量维护触及区域；只读任务不建文档，不全仓补齐、不写流水账。模板、来源/状态字段、继承与过期处理见[详细规范](references/directory-context.md)。
- DEBUG从会话/开发中提取并修正用户描述的正确使用和测试流程，保留原意、顺序、前提、预期与恢复。推送后、PR/分支合并后按影响范围对准确版本实际尝试相关流程；未部署/未合并/受阻明确未验，不拿编译、接口成功或读过流程冒充业务通过，也不自动授权部署或危险测试。
- 共享记忆类文件尽量带创建/最近修改日期，历史未知不补造；新增、修改、删除条目在文件内简记日期、条目标识、动作/原因，操作身份遵循 Commit 可见性规则：私有按 `##模型：` 要求，公开不记录操作模型身份；日期、条目标识与原因仍保留。删除仍留简短摘要/替代索引，文件更新时间不冒充验证日期；细则见[日期与修改身份](references/directory-context.md#日期修改身份与简短变更记录)。
- 普通Agent仅在有**九成以上把握**时剔除明显重复或无损整合；否则直接忽略该整理并保留原文。**内容压缩**通常仅由专门获授权允许的审计/辅助模型执行，不能把自认为有把握当授权，也不能借去重删掉独立信息。

## 工具类 Agent、Bot 与交互续行

- 本技能使用[LD角色与询问约定](references/interaction.md)：工具类Agent通常是Codex、Cursor、IDE AI插件、DeepSeekHarness等当前终端/宿主内的工具单元；Bot则是具人格配置、私有长期记忆/技能资料、聊天、A2A+Gateway协作及自身可操作环境的AI队友。不是行业标准或产品OS限制，也不按昵称提权。
- 工具类只在当前授权宿主原生问询，缺能力才用本机HTML辅助/同终端文字，**不得跨其他电脑或平台弹窗**；Bot在当前相关聊天渠道用原生卡片/文字，不开云服务器或其他电脑弹窗。只对真正需要人类决定的事项发问，提供方案差别、推荐理由和自定义输入；保留取消/稍后，不抢焦点，不默认多渠道重复通知。
- **没有回答不就此中止任务**：先核原授权、风险、可靠回档和业务方向影响；安全可逆且方向明确的可自行决定并留依据/回档方法，不自动采用推荐项。不安全、无法回档、涉及多业务方向而难裁决或需要新增批准的，仅暂缓该项，继续不依赖它的已授权内容，收尾结果集中问；未决不报完成。明确取消/拒绝/稍后不当沉默处理，不绕宿主审批。
- 明确无人值守不进入等待型询问。等待回答默认15分钟、可选空闲阈值独立配置，沿现有数据根/安装路径隔离，详情与实际配置路径由`show`显示；只在用户明确要求时修改。空闲不等于离开、未答不等于看过、未送达不等于无人，超时不提供新授权。当前本机辅助不监控键鼠，不能把配置已保存说成已检测。
- [本机辅助](scripts/interact.py)只收集答案，不执行方案；原生可用、Bot、无人值守或未允许本机UI时不启服务。按详细规则绑定请求/会话/修订、限制生命周期并回收结果；用户的新答案先核适用性。参数修改命令仍仅在[README参数设置](https://github.com/LastDreamTeam/LDAI_CodeStyleAgentSkill#参数设置)。

## 注释归属

- 人类名默认 `LD`，用户明确改配置后，新的 `<human_name>:` / 全角冒号形式也属于人类保护标记。**历史 `LD:`、现存人工标记和 `[debug]` 不因改名失去保护。**不全局替换源码、命名空间、来源或版权名。
- AI 不冒写、改写或认领人类标记；AI 自己产生的此类改动默认阻断。已确认来源、属于本次提交授权的人工改动可保留原文混合提交，不因有标记就重复逐行审批；来源或范围不清先核实，不擅自纳入人工未完成内容。
- AI 新增有维护价值的解释按实际提供方标记，如 `OpenAI:`、`Anthropic:`、`xAI:`、`Google:`、`DeepSeek:`；不以 `AI:` / `GPT:` 冒充可追溯提供方。身份不明就先核实。
- 保留准确的无前缀旧注释；不自动归类。完全失实的普通旧注释可在授权改动中替换为明确归属的新注释；受保护人工注释需人类确认。标记、目录或 Git 作者名都不等于已经人工审过。

## 提交格式

**先核实际目标仓库可见性，commit 前确认、push 前复核（包括fork/PR目标），不能凭 `private=false` 将企业internal当公开。**未知不默认私有，不向未核目标推送。

**公开仓库不记录整个 `#模型` / `##模型：` 或混合身份段**：首行只写具体改动摘要，空行后仍保留 `##问题：`、`##解决：`。不记录Bot/客户端、模型、计算机名或混合首行人类显示名，也不转填正文、trailer、PR和共享记忆。该例外优先于下文身份要求；合法版权/许可归属、真实贡献范围及人工保护不变，不自动改旧历史。

公开前必须检查并脱敏本次将公开的项目文件、配置/示例/日志/截图、共享记忆、PR说明及全部待推送提交（含中间版本与元数据）中的证件号、密钥等个人及企业内部隐私。敏感配置放环境变量或仓库外，公开示例仅占位；秘密已入历史时仅删除文件或加.gitignore不够，先停相关推送，已泄漏凭据由有权方撤销/轮换，不自行强推改历史。只核本次公开范围与相关风险，不扩成全机巡检；细则见[公开前隐私检查与脱敏](references/commit.md#公开前隐私检查与脱敏)。

首行生成器须显式传 `--visibility public|private`；公开模式只返回摘要与可见性，不读取/回显私密配置或机器身份，**不是自动秘密扫描器**。旧调用须补可见性参数，未核不得猜；详见[提交与验收](references/commit.md)。

以下三段身份格式**仅适用于经核私有仓库**，中文记录真实身份，不重写旧历史。三段之间保留空行，避免 Git 把正文合进提交标题。纯 Agent 改动：

```text
##模型：<产品短名或Bot名> + <实际模型标识> PC:<实际计算机名> | <本次具体改动短摘要>

##问题：真实症状、需求缺口或根因及其影响。

##解决：具体改动及理由；实际验证结果和未验证边界。
```

本次 staged 变更涉及 `LD:` / 自定义人类标记注释或其明确关联代码时，使用混合首行，不把整体成果完全算作 AI 自己的：

```text
##主人 + 模型：<产品短名或Bot名> + <实际模型标识> PC:<实际计算机名> | <本次具体改动短摘要>
```

`主人` 取当前配置 `human_commit_name`，不是把 `LD` 原样搬进提交；自定义后如 `##褪色的梦 + 模型：…`，不加 `【】`。问题/解决节不变，分别交代人类已有约定/实现和 Agent 本次工作；不能把继承的贡献说成人类本次亲写，也不能凭远处无关 `LD` 字样给所有提交加人类署名。没有 Bot 仅省略 Bot，精确模型和摘要仍必需；不把审查者当实现者。判定步骤与生成器见[提交与验收](references/commit.md)。

- 私有执行者写**产品短名或本人Bot名**，不写厂商前缀或拿 GitHub 账号代替：`OpenAI Codex` / `OpenAICodex` → `Codex`。**真实模型必填**，从当前会话/宿主有效配置/执行回执核实，不用产品名、厂商名、auto或未知占位代替；型号未核先查证。缩短产品名不等于截断准确模型ID。
- Codex、ClaudeCode、Cursor、VSCode/Visual Studio Copilot、其他本地 Agent 插件、DeepSeekHarness 等桌面/本地 Agent，在模型后追加 `PC:<实际计算机名>`，不使用冗长中文括号。运行环境读取，不能用登录名、仓库名或猜测值代替；远程执行标清实际主机，不误写成桌面客户端所在电脑。生成器仅对明确旧Codex产品名作兼容映射，不猜未知名字。
- 只有经核实具有独特、非默认名称的 Bot 才可沿用“真实 Bot 名 + 模型”而省略计算机名。Hermes/Grok/GPT Dot 是宿主或产品称呼，使用默认名的实例仍须追加计算机名；不能靠自称 Bot、临时编名字或填入 `--bot` 绕过。生成器默认加主机名，独特 Bot 须显式声明 `--named-bot`，细则见上述规范。
- 提交先简后繁：首行概括主要结果，问题节说明真实症状，解决节按实际改动、证据、限制展开。私有的新Agent原创提交，Git author/committer显示名也使用实际产品短名或本人名字，不用共用GitHub登录账号代替；只用已授权的单次提交/仓库局部设置，不改全局、邮箱绑定或历史，代提交保留真实作者。公开沿用获准的非敏感作者身份，不把模型/PC换填元数据；生成器自身不修改Git身份，细则见[显示名边界](references/commit.md#自己的名字git-显示名与-github-账号)。

## 流程与验收

1. 核适用范围、需求和可验收结果；抓取当前工作树基线，不以旧记录当现场。
2. 沿请求调用链读取所需契约/索引，先解决授权内目标；附近无关问题只作简短汇总，不扩成全仓审计。
   委派时交代明确范围、真实基线、依赖/接口约束与验收；主Agent复核整合diff和实际依赖，不能只采信子Agent的完成摘要。头衔或队友身份不自动授予架构裁决权，详见[协作契约](references/contract.md#修改迁移与验证)。
3. 复用当前有效模块；历史工程只提供行为参考，迁移不盲搬旧架构。不擅改插件、不直接手改 Unity 序列化场景/预制件，不覆盖人工未保存内容。
4. 修改后检查配对接口、Base 扩展面、XML 文档、命名空间、插件边界、Inspector Tooltip、注释归属、模块索引及序列化兼容；有实际增量时同步适用的目录共享文档，保护历史Readme和已有meta身份。
5. `.cs` 改动先用该终端可用的检查器过语法门禁，包含 `UNITY_EDITOR` 编译路径；缺依赖与语法错误分开，不假定某台机器私有脚本存在。
6. 再做项目真实编译与最小可运行入口验证。画面/听音/交互分别实际核验；语法通过不等于 Unity 编译，通过编译不等于效果验收。
7. 提交前逐项核目标可见性、staged paths、人工改动、对应公开/私有格式和真实验证边界；公开前核待推送历史与个人/企业隐私脱敏。任何失败不写成 PASS，不清理脏文件来掩盖问题。
8. 推送后回读远端准确提交，参考本区域 DEBUG 实际尝试受影响业务流程；合并后核合并结果并对新版本再测。未合并或没有加载目标版本时保留未验状态；只记录实际运行结果和范围，见[DEBUG回归规则](references/directory-context.md#推送后与合并后的回归)。

## 常见误用

- 不因为装了技能就把所有仓库改成 LD 架构；非 Unity 需明确选择与适配。
- 不把接口全锁死，也不把 Base/Agentic 当扩大权限的理由。
- 配置改名不是修改已有人工注释的授权，更不是改变版权主体。
- 不把许可共享义务等同于所有用技能开发的产品都必须开源。见 [许可分区](references/licensing.md)。
- 更新使用原生管理器或 Git fast-forward，不强制覆盖本地修改，不共享秘密，不修改其他技能。
