# LD CodeStyle Online

让人类通过 Markdown、自然语言和小而清楚的代码契约表达创意、设计与边界；Agent 承接可替换的实现与验证。本技能分层适用：**提交身份覆盖一切仓库；共享 Markdown 记忆默认覆盖一切项目；Unity/OOP 架构规则仅在适配范围使用。**不同引擎使用真实模块路径映射README与Agentic，不把Unity目录生搬过去。规则覆盖不代表所有宿主与引擎均已实机验收。本在线版基于 LD v6 实践整理，独立版本 **0.5.1**，不与旧版叠加执行。

本技能首先约束开发规范、习惯与风格，相对面向更多放权给 AI 的 Solo 开发者和希望减少代码失控的新手；不保证适合所有人，保障目标仍在完善、效果可能有限，不能代替测试和必要的人类判断。

## 何时启用

1. **提交身份是全仓库规则**：所有 AI 的新提交均适用，与引擎、语言、项目重量、是否采用OOP及共享记忆黑名单无关。私有按Bot/Agent强制准确身份；public按默认简化身份或主人明确要求执行。
2. **共享 Markdown 记忆采用默认启用、明确排除的黑名单规则**：当前宿主存在本技能时，Unity、UE/Unreal、Cocos、Godot及同类重型生产/工业引擎的一方项目强制应用；Web/H5、Vue、Node.js、PHP、TypeScript、Python及无底层引擎项目也默认启用，无需逐项目询问是否采用。主人明确要求某项目不使用共享记忆时，才记录其真实项目根到本机环境变量黑名单；不凭轻量、非Unity、旧项目或嫌麻烦自行排除。
3. 使用 `python -B scripts/project_memory.py show --project-root "<真实项目根>"` 查询当前项目。按[跨项目记忆与黑名单](references/memory-scope.md)识别真实根、映射模块路径与README同级逻辑范围；配置坏值报错，不假定启用/排除。排除仅停止本技能自动创建/维护该项目共享记忆，不删除既有资料、不关闭身份或版本健康要求，也不影响兄弟项目。只读任务仍按需读取，写任务才在触及区域建立/维护有真实内容的文档，不做全仓空模板铺设。
4. **其余源码风格与Unity/OOP规则单独判适配**：Unity工程须同时存在 `Assets/` 和 `ProjectSettings/ProjectVersion.txt`；用户已采用LD开发约定或一方源码有真实LD协作约定时启用相应规则。其他项目对源码架构、命名、注释、格式等按已有采用授权与语言适配范围执行；仅默认启用Markdown记忆和提交身份不等于自动采用全部源码规范。不要求所有项目建立Base接口、C#目录、Inspector或Unity资产结构；SQLite历史流程仍按已声明采用的区域执行。
5. 当前请求和最近工程规则优先；默认记忆维护不扩大业务任务、提交、发布、重构或第三方修改授权。生成代码、第三方原插件和无关工程不因路径映射被接管。

## 开工入口

- 读 [协作契约](references/contract.md)；读最近 `AGENTS.md`、模块说明、真实 Git 分支/HEAD/脏状态以及目标 Base/接口和活跃实现。按改动影响核真实入口、直接依赖与受影响调用者、装配/生命周期及验证入口；缺失上下文先定向补证据，不凭旧记忆、未搜到引用或编译缺包改写架构，也不为小修调查全仓。
- 处理目标路径内的脚本或资产前，按[目录共享上下文](references/directory-context.md)从共同入口、上层适用约定到所属区域 `README.md`，按需读取 `Agentic/USER.md`、`Agentic/MEMORY.md` 和相关 `Agentic/DEBUG.md` 条目，再沿直接依赖补查；不全仓注入，也不能只读叶子而漏掉上层联动约束。检查相关旧记忆入口，核逻辑作用域，物理目录不代表知识范围或权限。
- Core 工作另读 [README 模块索引与旧 Agentic.md 收敛](references/agentic.md)；模块索引由 README 承担，不再新建或续写 Agentic.md 平行正文，保留 Agentic/ 目录及宿主 AGENTS.md 的独立职责。索引不高于源码、序列化契约和当前人类指令。
- 使用终端工具运行 `python -B scripts/maintain.py show`（当前目录为本技能目录；或用脚本绝对路径），读取 `human_name`（默认 `LD`）及 `human_commit_name`（默认 `主人`）。两者分开，配置失败须报告，不覆盖损坏文件，也不猜用户设定。
- **默认强制维护，但只在相关任务触发**：开始使用本技能、执行依赖本技能的长任务时，必须运行 `python -B scripts/maintain.py sync --idle`；长任务跨日，在下一安全阶段再次检查。与本技能无关的任务不触发、不打断。技能不能自行运行，不安装后台任务，不把所有长任务都当成维护入口。
- **默认 `auto_update=true`，每天最多联网检查一次（滚动24小时）**；有新版且确认安全空档时直接更新，不逐次询问。尝试时间持久化，失败也节流；同日重复使用缓存，`--force` 也不突破每日检查上限。用户只要求检查时用 `check`，它不会更新。
- `--idle` 是调用方确认安装没有被其他任务占用，不是脚本自动探测。无法确认则仅 `check`，更新延后；长任务在途固定已读规则版本，阶段切换时确认空档、更新并重读后再采用新版本，不静默改写正在执行的约束。保留本地修改、固定分支和原生审批保护。
- 主人明确要求停止自动更新时按 README 修改当前实例开关。**关闭更新或版本落后，任一条件都必须标脏**；不健康不等于规范不可读、不可使用。旧配置的 `false` 不能凭猜测当成无人设置的默认而改开；保留并标脏，主人要求恢复时再开启。
- 用 `python -B scripts/maintain.py health` 读取当前安装版本、最近已知最新版、检查时间和健康原因；无网络，不把未检查、过期或失败冒充健康。依赖技能/插件可声明所需版本并用 `health --require-healthy --min-version <版本>` 在相关推送前检查；不通过时由依赖方按业务需要阻止该推送，不自动禁止全部业务。健康文件是保险信号，不是认证或全机已接入证明，详见[维护与健康接口](references/maintenance.md)。

## 用户提到可配置参数时

- “把技能里的 LD/人类注释标识改为某某”指 `human_name`；“把 Commit 里的主人改为褪色的梦/我的网名”指 `human_commit_name`。后者只改未来混合提交的显示名，不连带改前者。
- “开启/关闭技能自动更新”指 `auto_update`，关闭立即标脏。`interval_days`保留旧配置兼容值，在线实际检查固定每日最多一次；不能把更长旧周期当成不检查的理由。首次不强迫填写，示例、引述和普通称呼不是修改授权。
- 先用 `show` 定位当前安装和旧值，再按[README 参数设置](https://github.com/LastDreamTeam/LDAI_CodeStyleAgentSkill#参数设置)中的唯一修改命令入口，最小修改并回读。自然语言已明确字段和新值时直接执行；“改人类名”等语境不明时只确认歧义项。
- 只修改当前安装配置，不批量修改其他副本、源码标记、历史提交、版权来源、人格或 Git author/email。修改注释标识后旧 `LD:` 与已知人工标记仍受保护；配置损坏/非法值不得自行重置。此处只解释含义与安全边界，不重复参数修改命令。

## 人类与 Agent 的控制面

- **配对 Base 接口**是最后的强约束，不是所有 `interface` 都需要人类逐项审批。初建模块时可建立必要的 `I<ExactTypeName>Base`；建立后普通执行 Agent 不随意变更，必要时由人类或项目明确授权的架构负责人裁决。当前任务或既有项目授权已明确的裁决无需重复审批；可回档不替代依赖核查或新增授权。技能不自动任命任何 Bot 为负责人。
- **Base 是软实现层**，实现其配对接口，可由 AI 迭代，也允许人类参考/兜底实现。守住任务范围、公共 API、序列化和生命周期；不机械限制为只能微修。
- **Agentic 是可识别、可替换的 AI 实现边界**，默认就近目录及 `.Agentic` 命名空间。Base、复合业务、临时及明确独立脚本可有合理例外，不为了格式制造空层。
- Core 是带 Demo 的可提取零件库；允许随模块带走的单例工具、Model 集中入口，不提前强推 IoC、注册仪式或全面 UPM 化。
- 常驻业务在编辑态可查看、装配和调整。按需并存便捷的 InstanceMode 与显式 PrefabMode，两者复用同一能力；常驻实例不能因访问单例又偷偷造一份。成品挂具体派生实现，不以 Base 充当成品。

## 目录级共同记忆与用户意图

- 在实际模块/包/服务/功能责任区保留 `README.md`，有Base/配对接口的工程按其控制区定位；声明 `Agentic/MEMORY.md`、`Agentic/USER.md`、`Agentic/DEBUG.md` 的职责与入口，其他同类共享正文也集中在Agentic。Unity、UE、Cocos、Godot到Web/脚本项目均按[真实路径映射](references/memory-scope.md)适配；不要求目录字面叫Base或Scripts，也不为放记忆创建OOP结构。
- **打扫（不定期，不是每次任务）**：专门找出没按要求放的旧东西，保留有效正文、来源、链接和meta，搬回所属 README/Agentic；旧 Agentic.md 的有价值正文由 README 承接，不留双写。搬时留一行“从哪搬到哪、谁搬的”（公开身份按提交隐私规则处理）。旧代码缺注释、旧脚本没按新规一并放在打扫里；可分几次，做不完记一句“还差哪些”，下次接着清。安装/更新技能不自动开扫，只读不搬，不碰人工受保护内容或宿主私人记忆。
- **README原有职责与权威索引保持不变**，不随记忆搬迁，不退化为只剩链接的空壳。头部须自足地说明机制、同级区域作用域、MEMORY/USER/DEBUG真实入口及持久知识不可擅删/改作他用，让**未安装本技能**的Agent也能理解，不能只让它去安装技能或读外部链接。
- **每份文件头部都须独立可读，不能只在 README 写一次**：README、MEMORY、USER、DEBUG及同类共享记忆各自用简短基础提示说明本文件职责、持久共享而非临时/私有属性、真实scope与README入口、读写维护和权限边界。让未安装技能、不在舰队/指挥系统的Agent直接打开任何一份也能理解；不得只放链接，提示不充当System Prompt或新增授权。旧文件缺少说明的部分留到打扫时补齐，保留有效正文、历史与meta，不借补头部接管人工文件或扩成全仓重写；见[独立文件头部要求](references/directory-context.md#每份文件头部独立可读的基础说明)。
- 物理位置不改变逻辑范围：记忆跟随所属 **README 所在区域**及其明确声明；README 可与所说明的模块目录同级，正文存于该模块 Agentic/，须写真实往返入口。**不只管 Agentic、不扩大权限**；某一模块的条目不自动接管兄弟区域。
- **平时（任务中顺手做）**：记东西就放在它所属目录的 README/Agentic 里，别堆项目根目录、别放别人模块。平时，一条坑记在出事那块目录自己的 README/Agentic 里。**致命级例外优先**：死机、崩溃、掉数据、工程/存档损坏，要往外挪到「凡是动这块东西的人都得先看」的那一份文件（含它的索引）；XR 就是 XR 那套文件里最外面的那一份，不是项目根，也不是只留在出事那个子目录。条目标注「死机级」，带触发条件和一手证据（版本/提交）。README 是唯一索引；没有新信息就不记，详见[记在哪里](references/directory-context.md#记在哪里)。
- `MEMORY.md`记录脱敏共有事实/机制经验；`USER.md`记录有来源的用户持久要求/动态意图；`DEBUG.md`记录缺陷与防复发及用户视角的正确操作和测试流程；README负责区域声明和快速索引。缺陷正文可完整留在正确层级 DEBUG，不强迫另抄 MEMORY；可复用机制独立提炼并互链。
- **复发缺陷要沉淀有效修复经验**：工作会话发现或用户反馈反复出现，尤其Git曾修过时，核旧提交/diff与实际版本，在已验证修复后更新正确关联层级 DEBUG/MEMORY 的已有同类条目，保留发现、有效修复过程、验证与防复发边界，不复制两份。不收修复中途猜测/废弃方案的无价值流水；阶段性/番茄切片已成功验证即可记录，明确剩余未完成项，不必等整任务结束。旧经验遇反例先标待复核，新修复验证后再更新；见[修复经验闭环](references/directory-context.md#复发缺陷的修复经验闭环)。
- 这是项目共享文档，不是当前Bot的Hermes核心记忆；不同厂商Agent可读可维护。用户要求与Agent推断分开，未来设想不自动变成执行授权，一次性指令不升格为永久规则。
- 本组文档均是**可核参考，非绝对结论**。首次新增解释、经验和意图摘要默认暂定，按证据使用“可能/预计/估计/当前理解”等措辞；准确保留已测观察、真实路径和用户原话，不把事实故意写模糊，也不把一次成功扩成长期保证。
- 条目须经相关远端推送与重复核验：首次相关推送后超过 7 天可复核为持续观察；超过 15 天且多次相关推送（默认至少 3 次独立推送，含首次）、不同时间验证一致且无未解决反例，才可在**再次涉及**时考虑写为限定范围的基本稳定知识。时间/次数不自动证明正确，不为凑条件推送；证据不全则暂定，变化/反例则降级。日期和证据细则见[共享上下文成熟度](references/directory-context.md#参考措辞与知识成熟度)。
- `USER.md` 尽可能保留整理后的用户原话意图，区分摘录与“当前理解”的摘要，保留否定、条件和例外。成熟度约束的是Agent归纳；当前明确用户指令立即按范围生效，不等观察期，也不被旧摘要覆盖。
- 历史 `Readme.md` 默认是人类资料，**不覆盖、不改名、不自动改写**。先核大小写冲突与所有权；打扫时把已有同层 MEMORY/USER 或 AgentDocs 组按[兼容迁移规则](references/directory-context.md)保全迁入Agentic、修正声明和链接，不保留双份有效正文；人工冲突只阻断受影响项，不扩成无关工程搬迁。
- 授权写任务中按实际增量维护触及区域；只读任务不建文档，不全仓补齐、不写流水账。模板、来源/状态字段、继承与过期处理见[详细规范](references/directory-context.md)。
- DEBUG从会话/开发中提取并修正用户描述的正确使用和测试流程，保留原意、顺序、前提、预期与恢复。推送后、PR/分支合并后按影响范围对准确版本实际尝试相关流程；未部署/未合并/受阻明确未验，不拿编译、接口成功或读过流程冒充业务通过，也不自动授权部署或危险测试。
- 共享记忆类文件尽量带创建/最近修改日期，历史未知不补造；新增、修改、删除条目在文件内简记日期、条目标识、动作/原因，操作身份遵循 Commit 可见性规则：私有按Bot/Agent强制身份，公开默认昵称或具体模型名、不含推理强度，主人可调整；日期、条目标识与原因仍保留。删除仍留简短摘要/替代索引，文件更新时间不冒充验证日期；细则见[日期与修改身份](references/directory-context.md#日期修改身份与简短变更记录)。
- 普通Agent仅在有**九成以上把握**时剔除明显重复或无损整合；否则直接忽略该整理并保留原文。**内容压缩**通常仅由专门获授权允许的审计/辅助模型执行，不能把自认为有把握当授权，也不能借去重删掉独立信息。唯一例外：已采用[区域历史与有限摘要](references/memory-history.md)的区域，授权区域维护者可在精选原文入库、读回核验和旧摘要保全后压缩该区三份摘要；README/人类资料及未采用区域不适用此例外。

## 区域历史与有限摘要

处理共享记忆时必读[SQLite历史与摘要规范](references/memory-history.md)。所属README声明 `Agentic/history.sqlite3` 的真实入口和scope；只收本责任区用户相关原话与已验证debug修复/踩坑完整记录，保留来源、日期、条件和证据，不收全聊天或宿主私有记忆。三份Markdown保存当前有效关键摘要及少量历史ID，按需搜索索引后取原文，禁止全库注入或无限分卷。

USER/MEMORY/DEBUG默认字符硬上限分别为4000/6000/6000（含头部与索引，明确可调整，非用户亲定数字）；80%提示整理，超额拒写不截断。使用 `scripts/memory_history.py` 先入库读验，再以原文hash和记录ID替换候选，保留完整旧修订；缺库/损坏/漂移/超额不覆盖旧文。工具不自动理解原意或阻止外部编辑器，交付须检查实际三份文件和语义。SQLite不直接Git合并，历史共享必须让接手者可检索，默认不公开库/导出；详细命令与额度设置集中在README。

日期与类型使用独立`occurred_at/kind`列和索引，支持关键词/类型/日期区间组合查询；日期语义、未知值及schema 1→2保全导入见[历史规范](references/memory-history.md#日期与类型独立sql列和筛选)，不自动改写旧库。

## 工具类 Agent、Bot 与交互续行

- 本技能使用[LD角色与询问约定](references/interaction.md)：工具类Agent通常是Codex、Cursor、IDE AI插件、DeepSeekHarness等当前终端/宿主内的工具单元；Bot则是具人格配置、私有长期记忆/技能资料、聊天、A2A+Gateway协作及自身可操作环境的AI队友。不是行业标准或产品OS限制，也不按昵称提权。
- 工具类只在当前授权宿主问询，**不得跨其他电脑或平台弹窗**；Bot在当前相关聊天渠道使用原生卡片/文字。推送时应先尽力调查依赖、评估、实测与判断，最终仍不能安全可靠决策，尤其可能较大改变业务时才求助；给出已试证据、剩余未知、**至少两种可行推荐方案**及取舍/条件/验证回档理由，保留**用户自由解释**和其他方案入口，不能只抛问题或用取消凑第二方案。支持异步/后台询问时尽量不停独立工作；无可用询问功能则暂停当前任务，在同一会话带方案文字询问。超时或无可并行事项时报告待决、暂停相应推进；沉默不授权、不自动选推荐、不虚构异步能力。详见[推送前求助](references/interaction.md#推送前无法安全决策时的求助)。
- **没有回答不就此中止任务**：先核原授权、风险、可靠回档和业务方向影响；安全可逆且方向明确的可自行决定并留依据/回档方法，不自动采用推荐项。不安全、无法回档、涉及多业务方向而难裁决或需要新增批准的，仅暂缓该项，继续不依赖它的已授权内容，有可用询问能力时尽量途中带方案发问，收尾汇总仍待裁决项，不为等收尾推迟求助；未决不报完成。明确取消/拒绝/稍后不当沉默处理，不绕宿主审批。
- 明确无人值守不进入等待型询问。等待回答默认15分钟、可选空闲阈值独立配置，沿现有数据根/安装路径隔离，详情与实际配置路径由`show`显示；只在用户明确要求时修改。空闲不等于离开、未答不等于看过、未送达不等于无人，超时不提供新授权。当前本机辅助不监控键鼠，不能把配置已保存说成已检测。
- [本机辅助](scripts/interact.py)只收集答案，不执行方案；原生可用、Bot、无人值守或未允许本机UI时不启服务。按详细规则绑定请求/会话/修订、限制生命周期并回收结果；用户的新答案先核适用性。参数修改命令仍仅在[README参数设置](https://github.com/LastDreamTeam/LDAI_CodeStyleAgentSkill#参数设置)。

## 强制注释：平时写好，旧账另做打扫

写代码前必读[强制注释规范](references/comments.md)。平时，新写和改动的函数必须带有效头部文档，包括 private、构造函数、Unity 生命周期、辅助和测试方法；C# 等支持的位置用 XML，其他语言用有效原生形式。核心原理实现旁必须有 `//` 或该语言等价注释，说明原因、约束和关键顺序，两种说明不能互相代替。

旧代码缺注释、旧脚本没按新规，归不定期的专门打扫，不摊到每次任务。可分几次补，做不完记一句“还差哪些”；未改动的旧函数缺口不阻断本次提交。提交前核本次新写和改动的函数，不能将本次缺项冒充旧账；保护人工、第三方和生成代码，不重启暂停项目，也不冒称已安装自动源码门禁。

## 注释归属

- 人类名默认 `LD`，用户明确改配置后，新的 `<human_name>:` / 全角冒号形式也属于人类保护标记。**历史 `LD:`、现存人工标记和 `[debug]` 不因改名失去保护。**不全局替换源码、命名空间、来源或版权名。
- AI 不冒写、改写或认领人类标记；AI 自己产生的此类改动默认阻断。已确认来源、属于本次提交授权的人工改动可保留原文混合提交，不因有标记就重复逐行审批；来源或范围不清先核实，不擅自纳入人工未完成内容。
- AI 新增有维护价值的解释按实际提供方标记，如 `OpenAI:`、`Anthropic:`、`xAI:`、`Google:`、`DeepSeek:`；不以 `AI:` / `GPT:` 冒充可追溯提供方。身份不明就先核实。
- 保留准确的无前缀旧注释；不自动归类。完全失实的普通旧注释可在授权改动中替换为明确归属的新注释；受保护人工注释需人类确认。标记、目录或 Git 作者名都不等于已经人工审过。

## 默认提交与推送内容

默认同步**其他设备/干净检出能够完整复现更新所需的内容**：保全源码、资源、依赖声明、正式构建/测试脚本和必要文档；排除非必要的一次性调试脚本、实验现场、日志/转储/截图和中间产物。按实际用途判断，不凭扩展名一刀切。辅助材料已有主人明确纳入要求就遵守；否则先说明保留理由并按求助规范给方案，正常正式依赖不需重复审批。

Unity自动重新序列化中无必要业务语义的差异默认不上传；真正改变效果的资源/场景/预制件、配置、版本迁移及 `.meta` / GUID 依赖完整保留。**排除上传不等于删除本地文件**，不得为清空工作树删除、覆盖或回退人工/来源不明/其他任务资料；忽略规则按实际作用域，不隐藏必要依赖。

提交前核tracked、untracked、staged与真实diff，推送前检查**全部待推送提交**及中间版本，不能只看最终diff或最后一笔；`.gitignore`不移除已跟踪文件和历史。验证干净检出的相关正式流程不依赖排除物，未验如实写明。历史混入非必要文件时暂停受影响推送，按原权限处理，不自行强推或改写已发布历史；完整分类、示例和清单见[默认推送边界](references/commit.md#默认提交与推送边界完整复现更新)。

## 提交格式

**先核实际目标仓库可见性，commit 前确认、push 前复核（包括fork/PR目标），不能凭 `private=false` 将企业internal当公开。**未知不默认私有，不向未核目标推送。

**所有 AI 新提交必须准确署名，身份在明确可辨时尽量简短。**私有仓库强制 Bot 使用 `框架/容器名-昵称`，不需要模型；普通会话 Agent 使用 `框架/容器名 完整模型型号 推理强度`。身份字段不用 `+`，不以 `GPT`、`Sol`、`auto` 等模糊标签代替具体型号；确无推理档位时据实际声明 `none`，未知不得伪装成无档位。无需默认附加计算机名，仅按明确需要附真实 `PC:`。

**public 默认保留简化身份**：Bot 只用昵称，Agent 只用具体模型名（不含推理强度），不默认附框架、PC或混合人类显示名。主人可明确调整公开署名或要求省略；这不是私有强制规则的豁免。正文仍用空行分隔 `##问题：`、`##解决：`；合法版权/许可来源和真实贡献保留，不追改历史。

公开前必须检查并脱敏本次将公开的项目文件、配置/示例/日志/截图、共享记忆、PR说明及全部待推送提交（含中间版本与元数据）中的证件号、密钥等个人及企业内部隐私。敏感配置放环境变量或仓库外，公开示例仅占位；秘密已入历史时仅删除文件或加.gitignore不够，先停相关推送，已泄漏凭据由有权方撤销/轮换，不自行强推改历史。只核本次公开范围与相关风险，不扩成全机巡检；细则见[公开前隐私检查与脱敏](references/commit.md#公开前隐私检查与脱敏)。

首行生成器须显式传 `--visibility public|private`；公开模式只读取调用方已核的简化身份，不读取/回显私密配置或机器信息。工具只校验格式与明显占位，不能证明身份真实，也不是秘密扫描器。旧 public 摘要调用需要补具体模型/昵称，或在主人明确要求省略时传相应选项；详见[提交与验收](references/commit.md)。

三段之间保留空行，避免 Git 把正文合进标题。私有 Agent 的结构示意：

```text
##模型：<框架/容器名> <完整模型型号> <实际推理强度> | <具体改动摘要>

##问题：真实症状、需求缺口或根因及其影响。

##解决：具体改动及理由；实际验证结果和未验证边界。
```

私有 Bot 的身份部分改为 `<框架/容器名>-<昵称>`，不要求模型；公开则只保留昵称或不含推理强度的模型。Bot 须有可核实的独立姓名、记忆与资料，如 Grok Bot、GPT Dot、Hermes Bot、DSH Bot 的真实命名实例；仅品牌名或临时会话昵称不满足条件。Codex、Claude Code、Cursor、DSH、Copilot 等普通会话工具按 Agent 处理。模型和推理强度从当前会话、有效宿主配置或执行回执核实，不冒用示例。

本次 staged 变更涉及 `LD:` / 自定义人类标记注释或明确关联代码时，私有使用 `##主人 + 模型：<已核身份> | <摘要>`，其中 `主人` 取 `human_commit_name`。这个混合贡献前缀的 `+` 不是 AI 身份连接符。正文区分人类既有贡献与本次实现，不凭远处无关标记加署名、不把继承约定说成人类本次亲写，公开仍默认简化 AI 身份。

新原创提交的 Git author/committer 显示名遵循同一身份规则；若执行者有真实、可用、获准使用的自有邮箱，优先用作提交邮箱，没有则沿用获准邮箱或平台 noreply，不编造 Bot 邮箱、不冒充人类。只在本次进程或获准仓库局部设置，核 `git var` 和提交后元数据，不改全局/账号绑定/历史，代提交保留原作者。标题先简后繁、真实验证和未验边界见[显示名与提交说明](references/commit.md#自己的名字git-显示名与-github-账号)。

## 流程与验收

1. 核适用范围、需求和可验收结果；抓取当前工作树基线，不以旧记录当现场。
2. 沿请求调用链读取所需契约/索引，先解决授权内目标；附近无关问题只作简短汇总，不扩成全仓审计。
   委派时交代明确范围、真实基线、依赖/接口约束与验收；主Agent复核整合diff和实际依赖，不能只采信子Agent的完成摘要。头衔或队友身份不自动授予架构裁决权，详见[协作契约](references/contract.md#修改迁移与验证)。
3. 复用当前有效模块；历史工程只提供行为参考，迁移不盲搬旧架构。不擅改插件：优先项目侧扩展，确需侵入改写时最小化、就地标 `项目侧改写点`，并在插件目录外的必读入口登记清单，升级后按清单补回，见[插件纯净与必要改写](references/contract.md#插件纯净与必要改写)。不直接手改 Unity 序列化场景/预制件，不覆盖人工未保存内容。
4. 按[强制注释验收](references/comments.md#执行委派与提交验收)核本次新写和改动函数的头部、核心原理行注释与语义；委派同样说明范围，主Agent亲读源码复核，未改动旧函数的注释缺口留到打扫。按[代码格式整理](references/contract.md#代码格式整理)整理本次改动范围，保持原编码与换行，清理本次调试残留，不全文件重排。再核配对接口、Base 扩展面、命名空间、插件边界、Inspector Tooltip、注释归属、模块索引及序列化兼容；有真实增量才更新共享文档，保护历史Readme和已有meta。
5. `.cs` 改动先用该终端可用的检查器过语法门禁，包含 `UNITY_EDITOR` 编译路径；缺依赖与语法错误分开，不假定某台机器私有脚本存在。
6. 再做项目真实编译与最小可运行入口验证。画面/听音/交互分别实际核验；语法通过不等于 Unity 编译，通过编译不等于效果验收。
7. 提交前逐项核目标可见性、staged paths、人工改动、对应公开/私有格式和真实验证边界；公开前核待推送历史与个人/企业隐私脱敏。任何失败不写成 PASS，不清理脏文件来掩盖问题。
8. 推送后回读远端准确提交，参考本区域 DEBUG 实际尝试受影响业务流程；合并后核合并结果并对新版本再测。未合并或没有加载目标版本时保留未验状态；只记录实际运行结果和范围，见[DEBUG回归规则](references/directory-context.md#推送后与合并后的回归)。

## 常见误用

- 不把三层范围混为一谈：身份覆盖所有仓库，共享Markdown记忆默认开启/明确项目黑名单，Unity/OOP架构才需独立授权与适配。不能用“非Unity”或“不采用LD架构”绕过前两层。
- 不把接口全锁死，也不把 Base/Agentic 当扩大权限的理由。
- 不为消除眼前报错删引用、加替代桩或改插件原件来“拆东墙补西墙”；先核调用链与影响范围，修复后把有效经验写入所属区域记忆，防止复发。
- 配置改名不是修改已有人工注释的授权，更不是改变版权主体。
- 不把许可共享义务等同于所有用技能开发的产品都必须开源。见 [许可分区](references/licensing.md)。
- 更新使用原生管理器或 Git fast-forward，不强制覆盖本地修改，不共享秘密，不修改其他技能。
