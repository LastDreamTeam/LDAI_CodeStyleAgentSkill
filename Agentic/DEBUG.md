## 流程：规范与CLI回归

前提：Python3.10+、Git，当前目录为本仓库根；CI另提供Node语法检查。配置/状态及Git测试使用临时目录，不修改真实用户黑名单。

1. 运行 `python -B -m unittest discover -s tests -v`，分别核提交身份、每日节流、健康门禁、环境变量策略及既有历史/交互工具。
2. 运行 `node --check skills/ld-codestyle-online/assets/question.js` 和 `git diff --check`。
3. 推送后核准确分支SHA及CI矩阵；合并后对准确合并版本再检查。不能将分支结果冒称合并版本已验，不能将模拟registry/更新后端称为全部宿主实机通过。
4. 发版包仅从准确Git树生成，完整技能含许可、版本和全部脚本；解包后运行维护、身份及项目策略CLI，校验文件摘要和来源提交。

已核环境边界：2026-11-11，0.5.0开发回归时，本机3项安装链接测试因Windows `WinError 1314`（无符号链接特权）失败；同日未修改主线 `0d8b7eb` 的相同3项复现同一错误。不得把它算通过，也不得靠修改全机权限或跳过保护来掩盖。其他平台/Windows runner结果需从对应CI实际回读；此记录不预填发版成功。

## 流程：依赖方采用健康门禁

- 在技能相关任务入口按安全空档执行 `sync --idle`，只要版本落后或更新关闭，健康必须标脏；同日重复不重新联网检查。
- 相关推送前使用 `health --require-healthy --min-version 0.5.0`；退出3代表健康不满足，4代表版本不满足。仅运行普通`health`返回0不能当作通过门禁。
- 过期、损坏或中断状态必须保留未知/失败，不把缓存曾健康当成永远健康；任务无关时不触发维护。

## 流程：项目记忆默认与明确排除

- 用 `project_memory.py show --project-root "<真实项目根>"` 确认默认启用；此查询不应写业务文件或联网。
- 只有主人明确要求才调用exclude/include。默认候选输出必须 `persisted=false`，当前`enabled`不应被候选值冒充。
- Windows持久化只访问指定用户环境变量，写后回读；其他系统按实际宿主环境入口保存后再查询，不能说建议已生效。测试坏JSON、别的根、兄弟前缀、路径别名和旧继承环境，排除不删除共享文件或禁用身份规则。
- 本仓库真实用户环境未被测试排除；自动测试用隔离数据/registry替身。各引擎实际资产导入和跨设备共享效果仍需相应项目验收。

## 流程：默认交付范围与最终求助（Issue #21）

1. 运行 `python -B -m unittest discover -s tests -p test_push_scope.py -v`，验证精确候选保全源码、正式测试、资源及对应元数据；干净clone能执行正式夹具测试，一次性探测/日志和人工dirty内容留在原地且字节不变。
2. 缺失必要 `.meta` 的负例必须因该文件缺失而失败，不能把任意退出1算验证成功；最终树删掉副产物的历史案例仍应在全部待推送提交里发现前一版本。
3. 问询模板必须兼容既有QuestionSession，两种实质方案与纯自由文本均能回传；业务方向未定时超时不自动选推荐、不签发推送许可。
4. 语义复核入口：已尽合理努力核查才求助、重大业务影响、支持异步则途中询问并继续独立工作、无可用询问功能则暂停同会话提问，超时/无并行任务保留待决；只有阻塞式能力不能被误写成无询问能力，收尾仅汇总而不延迟首次求助。
